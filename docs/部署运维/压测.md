# 压测

压测脚本在 `deploy/loadtest/`，使用 [k6](https://k6.io/)。它在独立的 Compose 项目（`jikelog-loadtest`）中启动与正式环境相同的镜像和资源参数，测完连同数据一起删除，不影响正式数据。

## 1. 性能目标与场景

| 目标（实施计划） | 场景 | 指标 |
|---|---|---|
| 同区域接口 p95 < 100ms | `api`：每秒 30 组常用读接口（个人信息、增量拉取、附件用量） | `http_req_duration{kind:api}` |
| 500 条变更的推送与拉取 p95 < 200ms | `sync500`：每秒一轮，推送 500 条工作日志，再拉取这 500 条并抽查解密 | `sync_push_500_total`、`sync_pull_500_total` |
| 实时通知 1 秒内到达 | `realtime`：设备 B 保持 WebSocket 连接，设备 A 每秒推送一条 | `realtime_notify`（从 A 发出推送到 B 收到通知） |

- 一次推送最多 100 条、一页最多返回 100 条（接口限制），所以 500 条是 5 次请求，按 5 次的总耗时计算。
- 工作日志的内容与地点和 App 一样用传输会话密钥加密。会话密钥由 `e2e-keys.sh` 用 OpenSSL 预先算好，k6 中只做 AES-GCM。
- 另有错误率 < 1%、检查通过率 > 99% 两个阈值。

## 2. 运行

需要 Docker 与 OpenSSL 3：

```bash
# 构建 API 镜像（国内网络加 --build-arg GOPROXY=https://goproxy.cn,direct）
docker build -t jikelog-api:loadtest server
bash deploy/loadtest/run.sh jikelog-api:loadtest
```

- 环境变量：`DURATION`（默认 `2m`）、`API_RATE`（默认 30）、`SYNC_RATE`（默认 1）、`USERS`（默认 8 个账号，每个账号两台设备）。
- 结果在终端，以及 `deploy/loadtest/results/summary.json`。任一阈值未达标时退出码非零。
- 在服务器上运行时，把 `deploy/loadtest/` 与镜像复制过去执行，测完删除。

## 3. 结果

### 2026-10-13，v0.9.0

**环境**：k6 与被测服务在同一台服务器上，即 2 核 1.7G 的 ECS。k6 自身也要占用 CPU（每轮需要加密 500 条记录），所以结果偏保守。

| 指标 | 目标 | 优化前（本机） | 本机 | 服务器 | 服务器（读接口降到每秒 1 组） |
|---|---|---|---|---|---|
| 读接口 p95 | < 100ms | 2.2ms | 2.3ms | 11.8ms | 8.0ms |
| 推送 100 条 p95（单次请求） | — | 76.7ms | 31.2ms | 97.4ms | 56.5ms |
| 推送 500 条 p95（5 次合计） | < 200ms | 350.9ms | 129.7ms | **357.0ms**（中位数 261.8ms） | **242.1ms**（中位数 180.9ms） |
| 拉取 500 条 p95（5 页合计） | < 200ms | — | 22.5ms | 114.8ms | 76.8ms |
| 实时通知 p95 | < 1s | 54.2ms | 13.4ms | 55.0ms | 33.0ms |
| 错误率 | < 1% | 0% | 0% | 0% | 0% |

- 服务器上 2 分钟共 12,312 个请求，约每秒 101 个，CPU 约 70% 忙（含 k6）。压测服务的内存：api 18MB、PostgreSQL 110MB、对象存储 61MB、Redis 6MB。
- **优化**：推送原先每条变更要查询 3 次数据库：读取并锁定记录、检查 ID 是否被其他账号占用、插入。现在改为：
  - 整批的记录与 ID 占用各用一次查询读出；
  - 新记录的插入排队后通过 pgx 管道一次发出。
  - 本机推送 100 条从 62ms 降到 21ms（平均）。
- **未达标**：服务器上推送 500 条（5 次请求）的 p95 超过 200ms。每次请求的耗时主要在 PostgreSQL 写入 100 行与提交上，Go 代码只占约 13ms。2026-10-13 决定暂时接受现状。以后需要时可选的改进：
  - 升级到 4 核或更高主频的规格；
  - 把单次推送上限从 100 提高到 500，减少 4 次往返与提交（需要同时修改 App）；
  - 把 k6 放到同地域的另一台机器上复测，结果会更接近真实情况。
- App 冷启动 < 1.5s 需要在真机上测量，不在本压测范围内。
