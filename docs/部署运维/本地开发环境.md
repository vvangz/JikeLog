# 本地开发环境

## 1. 安装工具

| 工具 | 版本 | 说明 |
|---|---|---|
| Git | 2.40+ | 需配置 `user.name` 与 `user.email` |
| Go | 1.27.2 | 只要本机有 Go 1.21 及以上，`GOTOOLCHAIN=auto` 会按 `server/go.mod` 自动下载 1.27.2 |
| Node.js | 22 LTS | — |
| pnpm | 10.33 | `corepack enable` 或 `npm i -g pnpm` |
| Flutter | 3.47.6 stable | 国内建议设置镜像：`PUB_HOSTED_URL=https://pub.flutter-io.cn`、`FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn` |
| JDK | 17 | Android 构建需要，`JAVA_HOME` 要指向 JDK 17 |
| Android Studio | 最新稳定版 | 提供 Android SDK 与模拟器；装好后执行 `flutter doctor --android-licenses` |
| Docker Desktop | 27+ | 用于运行 PostgreSQL / Redis / 对象存储 |
| gitleaks（可选） | 8.30+ | 本地提交前扫描密钥：`winget install Gitleaks.Gitleaks` |

用 `flutter doctor` 检查 Flutter 环境。

## 2. 初始化

```bash
git clone https://github.com/vvangz/JikeLog.git && cd JikeLog
pnpm install                  # 安装依赖，同时安装 Git 钩子（commitlint、gofmt、eslint、dart format）
bash scripts/fetch-fonts.sh   # 下载字体（首次约 230MB，之后读缓存 .cache/fonts）
```

## 3. 启动依赖服务

```bash
cp deploy/.env.example deploy/.env      # 按需修改本地密码
docker compose -f deploy/docker-compose.dev.yml --env-file deploy/.env up -d
docker compose -f deploy/docker-compose.dev.yml ps
```

| 服务 | 地址 | 说明 |
|---|---|---|
| PostgreSQL 17 | `127.0.0.1:5432` | 数据库、用户名、密码见 `deploy/.env`；端口可用 `POSTGRES_PORT` 修改 |
| Redis 7.4 | `127.0.0.1:6379` | 密码为 `REDIS_PASSWORD`；本机 6379 已被占用时设置 `REDIS_PORT`，并同步修改 `JIKELOG_REDIS_URL` |
| RustFS（S3 兼容） | API `127.0.0.1:9000`，控制台 `127.0.0.1:9001` | 账号为 `S3_ACCESS_KEY` / `S3_SECRET_KEY` |

端口只绑定 127.0.0.1，局域网无法访问。

## 4. 运行各端

```bash
# 服务端（配置项见下表）：先加载 deploy/.env，执行数据库迁移，再启动 API
set -a && source deploy/.env && set +a
cd server
go run ./cmd/migrate
go run ./cmd/api
curl http://127.0.0.1:8080/readyz         # 数据库与 Redis 都就绪时返回 200

# 开发环境使用模拟短信，验证码打印在 API 日志里，形如：
#   msg="mock sms sent（仅开发环境）" phone=138****8000 purpose=login code=123456

# 管理后台（/api 会被代理到 8080）
pnpm --filter @jikelog/admin-web dev

# Android（需先启动模拟器或连接真机）
cd apps/mobile && flutter run
```

真机调试时，App 默认连接 `10.0.2.2`（模拟器访问宿主机的地址），需要改用 adb 转发：

```bash
adb reverse tcp:8080 tcp:8080   # API
adb reverse tcp:9000 tcp:9000   # 对象存储（附件直传直下）
flutter run --dart-define=JIKELOG_API_BASE=http://127.0.0.1:8080
```

同时把 `deploy/.env` 中的 `JIKELOG_STORAGE_PUBLIC_ENDPOINT` 改为 `http://127.0.0.1:9000`，否则附件上传地址会指向 10.0.2.2。

App 默认内置开发示例的传输加密公钥（与 `.env.example` 中的示例私钥配对），只有调试构建允许使用。

- 连接验收或生产服务器的构建，用 `--dart-define=JIKELOG_E2E_PUBLIC_KEY=<服务器公钥>` 传入对应的公钥。
- 本地用 profile 构建联调（例如 Web 端到端测试）时，需要加 `--dart-define=JIKELOG_ALLOW_DEV_E2E_KEY=true` 显式允许示例公钥。
- release 构建一律不允许使用示例公钥。

修改 `apps/mobile/lib/core/db/database.dart`（本地数据库表结构）后，需要重新生成代码：

```bash
cd apps/mobile && dart run build_runner build --delete-conflicting-outputs
```

笔记的富文本编辑器是独立的前端工程 `apps/note-editor`（Tiptap，见 ADR-007），构建为单个 HTML 文件 `apps/mobile/assets/editor/index.html` 随 App 打包。修改编辑器源码后需要重新构建并提交构建产物（CI 会检查两者一致）：

```bash
pnpm --filter @jikelog/note-editor build
```

在浏览器中调试编辑器：`pnpm --filter @jikelog/note-editor dev`，页面需要一个模拟的 `window.JikeLog.postMessage` 通道，可在控制台中用 `window.jikelog.receive('{"type":"init",...}')` 发送消息。

## 5. 服务端环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `JIKELOG_ENV` | `development` | 可选 `development` / `test` / `staging` / `production`；非 development 时 Gin 使用 release 模式 |
| `JIKELOG_HTTP_ADDR` | `127.0.0.1:8080` | 监听地址；默认只监听本机，容器镜像中为 `:8080` |
| `JIKELOG_HTTP_READ_TIMEOUT` | `15s` | 读超时（同时作为请求头读取超时） |
| `JIKELOG_HTTP_WRITE_TIMEOUT` | `30s` | 写超时 |
| `JIKELOG_HTTP_IDLE_TIMEOUT` | `60s` | Keep-Alive 空闲超时 |
| `JIKELOG_HTTP_SHUTDOWN_TIMEOUT` | `8s` | 收到 SIGTERM 后的优雅关闭时限，需小于容器停止宽限期（Docker 默认 10s） |
| `JIKELOG_HTTP_TRUSTED_PROXIES` | 空 | 可信反向代理 IP/CIDR，逗号分隔；为空时不信任 `X-Forwarded-For`。**生产环境必填**（否则所有请求的客户端 IP 相同，限流会误伤全部用户），且禁止 `0.0.0.0/0`、`::/0` |
| `JIKELOG_HTTP_CORS_ORIGINS` | 空 | 允许跨域的来源，逗号分隔，形如 `https://admin.example.com`；为空时不返回 CORS 头；生产环境只允许 https |
| `JIKELOG_DB_URL` | **必填** | `postgres://user:pass@host:5432/db?sslmode=require` |
| `JIKELOG_DB_MAX_CONNS` | `20` | 连接池上限 |
| `JIKELOG_REDIS_URL` | **必填** | `redis://:pass@host:6379/0`，TLS 用 `rediss://` |
| `JIKELOG_AUTH_JWT_SECRET` | **必填** | Access Token 签名密钥，至少 32 字节；staging / production 不能包含示例中的 `change-me`。也用于派生短信验证码的 HMAC 密钥 |
| `JIKELOG_AUTH_JWT_PREVIOUS_SECRET` | 空 | 轮换密钥时填旧密钥，旧令牌在其有效期内继续可用；15 分钟后即可删除 |
| `JIKELOG_AUTH_ACCESS_TTL` | `15m` | Access Token 有效期，最长 1 小时 |
| `JIKELOG_AUTH_REFRESH_TTL` | `720h` | Refresh Token 有效期（30 天，每次刷新顺延） |
| `JIKELOG_SMS_PROVIDER` | `mock` | `mock`（验证码写入日志，staging / production 禁用）/ `aliyun`（v0.9.0 接入） |
| `JIKELOG_CAPTCHA_PROVIDER` | `none` | 发送短信前的人机验证：`none`（staging / production 禁用）/ `aliyun`（v0.9.0 接入） |
| `JIKELOG_E2E_PRIVATE_KEY` | **必填** | 工作日志传输加密的服务端 X25519 私钥（base64，32 字节），对应公钥编译进 App（ADR-006）。staging / production 不能使用 `.env.example` 中的示例私钥 |
| `JIKELOG_E2E_PREVIOUS_PRIVATE_KEY` | 空 | 轮换时填旧私钥，新旧版本 App 共存期间都能握手 |
| `JIKELOG_KMS_PROVIDER` | `local` | `local`（主密钥来自下一项，开发和测试用）/ `aliyun`（v0.9.0 接入） |
| `JIKELOG_KMS_LOCAL_MASTER_KEY` | **必填**（local 时） | 落库加密主密钥（base64，32 字节），用来包裹每个账号的数据密钥。staging / production 不能使用示例值 |
| `JIKELOG_STORAGE_ENDPOINT` | **必填** | 服务端访问对象存储的地址，如 `http://127.0.0.1:9000`、`https://oss-cn-beijing-internal.aliyuncs.com` |
| `JIKELOG_STORAGE_PUBLIC_ENDPOINT` | 同上一项 | 客户端直传直下的地址，用于生成预签名 URL：模拟器为 `http://10.0.2.2:9000`；生产环境必须是 https |
| `JIKELOG_STORAGE_BUCKET` | `jikelog` | 存储桶；开发环境启动时自动创建，生产环境由运维预先创建并设为私有 |
| `JIKELOG_STORAGE_ACCESS_KEY` / `_SECRET_KEY` | **必填** | 对象存储访问密钥 |
| `JIKELOG_STORAGE_REGION` | `us-east-1` | 区域（签名用），阿里云 OSS 填实际区域如 `oss-cn-beijing` |
| `JIKELOG_STORAGE_PATH_STYLE` | `true` | RustFS / MinIO 用路径风格；阿里云 OSS 需设为 `false` |
| `JIKELOG_ATTACHMENT_MAX_SIZE` | `104857600` | 单个附件上限（字节，默认 100MB） |
| `JIKELOG_ATTACHMENT_QUOTA` | `2147483648` | 每个账号的附件总量上限（字节，默认 2GB） |
| `JIKELOG_PUSH_PROVIDER` | `log` | 备忘录提醒的服务端推送（ADR-008）：`log`（只记日志，提醒完全依赖 App 本地闹钟）/ `jpush`（极光推送） |
| `JIKELOG_PUSH_JPUSH_APP_KEY` / `_MASTER_SECRET` | **必填**（jpush 时） | 极光控制台中应用的 AppKey 与 Master Secret |
| `JIKELOG_PUSH_JPUSH_ENDPOINT` | `https://api.jpush.cn/v3/push` | 极光推送 API 地址，必须是 https |
| `JIKELOG_LOG_LEVEL` | `info` | `debug` / `info` / `warn` / `error` |
| `JIKELOG_LOG_FORMAT` | `json` | `json` / `text` |

配置非法时服务拒绝启动，并列出全部错误。

## 6. 测试与检查

```bash
bash scripts/go-coverage.sh                        # Go 测试 + 覆盖率 ≥ 80%（数据库集成测试需要 Docker，未启动时自动跳过）
pnpm --filter @jikelog/design-tokens test          # 设计令牌（含对比度）
pnpm --filter @jikelog/admin-web test:coverage     # 管理后台
pnpm --filter @jikelog/note-editor test:coverage   # 笔记富文本编辑器（Markdown 往返、消息协议）
cd apps/mobile && flutter analyze && flutter test --coverage
# Windows 上测试并行启动偶发 "Connection closed before test suite loaded"，可以加 -j 1
```

## 常见问题

- **`go test` 报 "exec format error"**：全局 `go env` 设置了 `GOOS=linux`。可以临时执行 `GOOS=windows go test ./...`，也可以直接用 `scripts/go-coverage.sh`
- **Flutter 构建提示找不到 `assets/fonts/...`**：还没执行 `bash scripts/fetch-fonts.sh`
- **Windows 上对象存储集成测试报 "forbidden by its access permissions"**：testcontainers 把 localhost 解析为 IPv6 `::1`。可以自己启动一个只监听 IPv4 的 RustFS，再用 `JIKELOG_TEST_S3_ENDPOINT` 指过去：
  ```bash
  docker run -d --name jikelog-test-s3 -p 127.0.0.1:19000:9000 -e RUSTFS_ACCESS_KEY=jikelog-test -e RUSTFS_SECRET_KEY=jikelog-test-secret rustfs/rustfs:1.0.1
  JIKELOG_TEST_S3_ENDPOINT=http://127.0.0.1:19000 bash scripts/go-coverage.sh
  ```
- **Windows 上 `flutter test` 报 "Connection closed before test suite loaded"**：并行启动多个测试进程时偶发，测试本身没有问题。改为串行运行：`flutter test --concurrency=1`，或 `FLUTTER_TEST_ARGS=--concurrency=1 bash scripts/flutter-coverage.sh`
- **Go 集成测试在 Windows 上启动对象存储容器失败（"forbidden by its access permissions"）**：随机映射的端口落在了系统保留范围内，测试会自动换端口重试 3 次；仍失败时重新运行即可
- **pnpm 提示 openapi-typescript 的 peer 依赖要求 typescript@^5**：可以忽略。它只用于生成类型，在 TS 6 下运行正常
