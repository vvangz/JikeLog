# 备份与恢复

需求第 10 条：数据备份周期为 14 日。设计见 [ADR-012](../架构/ADR/ADR-012-单机部署与备份.md) 第 4 节。

## 1. 备份内容与方式

| 项目 | 说明 |
|---|---|
| 周期 | `backup` 容器每天 03:30（北京时间）检查，距上次成功备份满 14 天（`BACKUP_INTERVAL_DAYS`）就执行 |
| 内容 | `db.dump`（PostgreSQL 全量，`pg_dump -Fc`）、`objects/`（附件存储桶）、`env`（服务器 `.env`）、`manifest.json`（各表行数与附件数，恢复后用来校验；行数从 `db.dump` 中统计，与导出是同一个快照） |
| 加密 | 打包后用 age 公钥（`BACKUP_AGE_RECIPIENT`）加密为 `jikelog-<时间>.tar.age`；服务器上没有私钥 |
| 存放 | 服务器 `backups/` 保留最近 6 份（`BACKUP_KEEP`）；配置了 OSS 时同时上传到另一地域的存储桶，由存储桶的生命周期规则在 90 天后删除 |
| OSS 权限 | 服务器上的 AccessKey 只能写入（`backup.env`），不能读取、列出或删除已有的备份 |
| 结果 | 写入 `backups/status.json`；`last-success` 记录最近一次成功的时间 |

导出文件 24 小时后就会删除，不在备份范围内。

为什么要备份 `.env`：数据库中的敏感字段由各账号的数据密钥加密，数据密钥又由 `.env` 中的本地主密钥（`JIKELOG_KMS_LOCAL_MASTER_KEY`）加密。没有主密钥，数据库备份无法解开。

部署时还会单独做一次数据库备份，保存在 `backups/predeploy/`（未加密，权限 600，保留 5 份），用于回退有问题的版本，见[《生产部署》](生产部署.md)第 3 节。

## 2. 日常检查

```bash
cd /root/jikelog
bash scripts/check-backup.sh          # 超过 15 天没有成功备份时返回 1，可以接入定时任务或监控
cat backups/status.json
docker compose logs --tail 50 backup  # 每次检查与备份的日志
```

立即备份一次：

```bash
docker compose run --rm backup backup-now
```

备份失败的常见原因：

| 日志 | 处理 |
|---|---|
| 未设置 BACKUP_AGE_RECIPIENT | 在 `.env` 中填上 age 公钥，然后 `docker compose up -d backup` |
| 上传 OSS 失败 | 检查 `backup.env` 中 OSS 的地址、存储桶与 AccessKey（修改后执行 `docker compose up -d --force-recreate backup`）；本地备份已经保留 |
| 警告：未配置异地 OSS | 只有本地备份，服务器损坏时备份也会丢失，尽快配置 OSS |

## 3. 恢复

恢复需要 age 私钥文件，只在恢复时临时放到服务器上，用完立即删除。

### 3.1 恢复演练（不影响正式数据）

建议每季度做一次，以及每次修改备份配置之后：

```bash
cd /root/jikelog
# 需要 OSS 上的备份时：服务器上的 AccessKey 只能写入，用阿里云控制台或 ossutil（主账号）下载后上传到服务器
bash scripts/restore.sh backups/jikelog-<时间>.tar.age /root/jikelog-backup.key
rm /root/jikelog-backup.key
```

脚本会：

1. 解密并解包到临时目录。
2. 核对附件数与 manifest 一致。
3. 启动一个临时的 PostgreSQL，把数据库恢复进去。
4. 核对各表行数与备份时一致。
5. 删除临时数据库和解包的文件。

### 3.2 正式恢复（覆盖当前数据）

```bash
bash scripts/restore.sh backups/jikelog-<时间>.tar.age /root/jikelog-backup.key --production
```

- 需要输入 `RESTORE` 确认。
- 停止 api 与 backup → 用备份覆盖数据库（`pg_restore --clean`）→ 核对行数 → 把附件复制回存储桶 → 启动服务。
- 备份中的 `.env` 保存为 `.env.from-backup`。如果是换了一台新服务器，或 `.env` 已丢失，先用它替换 `.env`，再启动服务。

### 3.3 整台服务器损坏

1. 新服务器安装 Docker，按[《生产部署》](生产部署.md)第 1.4 节配置部署密钥。
2. 用阿里云控制台或 ossutil 从 OSS 下载最近的备份，用私钥解开，取出 `env` 作为新服务器的 `/root/jikelog/.env`：

   ```bash
   age -d -i jikelog-backup.key jikelog-<时间>.tar.age | tar -xOf - env > /root/jikelog/.env
   chmod 600 /root/jikelog/.env
   ```

3. 运行"部署"工作流（需要先修改 `DEPLOY_HOST` 等 Secrets），部署与备份时相同的版本。
4. `bash scripts/restore.sh <备份文件> <私钥文件> --production`。
5. 修改域名解析到新服务器。

## 4. 已知限制

- 备份只加密、没有签名：任何人都可以用公钥加密一份伪造的备份。服务器上的 AccessKey 只能写入，OSS 又开启了版本控制，伪造的文件无法覆盖真实备份；恢复时只使用由备份任务按时生成、时间与 `status.json` 对得上的文件。
- 部署前的数据库备份（`backups/predeploy/`）没有加密，与数据库、主密钥在同一台服务器上，不增加泄露面。
