# 管理员手册

> 适用版本：v0.8.0 及以上

Web 管理后台供运营与运维人员查看用户的使用概况和配置，排查"收不到提醒""同步不上"等问题。

**管理员只能查看，不能修改用户数据，也看不到工作日志、笔记、备忘录和记账的任何内容。**所有查看与管理操作都会写入审计日志。设计说明见 [ADR-011](架构/ADR/ADR-011-管理后台.md)。

## 1. 创建第一个超级管理员

管理员账号与 App 用户账号是两套账号，互不相通。第一个超级管理员需要在服务器上用命令行创建：

```bash
cd /root/jikelog
# 输入密码时不回显，密码不会留在命令历史中
read -s -p "密码：" PW && echo
echo "$PW" | docker compose run --rm -T --entrypoint jikelog-admin api create -username root -role super_admin
unset PW
```

- 用户名为 4–20 位字母、数字或下划线，以字母开头。
- 密码至少 10 位，同时包含字母和数字。

之后的管理员由超级管理员在后台创建（第 6 节）。

**忘记密码**：超级管理员可以在后台重置其他管理员的密码。如果唯一的超级管理员忘记了密码，在服务器上执行：

```bash
read -s -p "新密码：" PW && echo
echo "$PW" | docker compose run --rm -T --entrypoint jikelog-admin api reset-password -username root
unset PW
```

重置后，该管理员原有的登录全部失效。

## 2. 登录与账号安全

打开管理后台，输入用户名和密码登录。

- **首次登录**：由其他管理员新建的账号，或被重置过密码的账号，第一次登录时必须先修改密码，改完才能使用其他页面。
- **失败锁定**：
  - 同一账号在同一网络中 15 分钟内输错 5 次，锁定到 15 分钟结束。换一个网络（例如手机热点）不受影响。
  - 同一账号每小时最多输错 30 次；同一网络 15 分钟内最多尝试 20 次。
  - 修改密码时，当前密码 15 分钟内最多输错 5 次。
- **会话**：
  - 登录状态保存在浏览器中，最长 12 小时，到期后需要重新登录。
  - 关闭再打开页面不用重新登录。可以同时打开多个标签页。
  - 连不上服务器时页面显示"无法连接服务器"，网络恢复后点击重试即可，不需要重新登录。
- **修改密码**：在 **账号** 页面修改。修改后，其他浏览器上的登录立即失效。
- **退出**：在 **账号** 页面点击 **退出登录**。

## 3. 仪表盘

| 指标 | 说明 |
|---|---|
| 用户总数 | 已注册的账号数 |
| 今日新增 | 今天（北京时间）注册的账号数 |
| 今日活跃 / 近 7 天活跃 / 近 30 天活跃 | 在这段时间内有设备使用过 App 的用户数 |
| 附件总用量 | 全部用户上传的附件大小之和 |
| 近 30 天新增用户 | 每天新注册的账号数，鼠标停在柱子上显示具体数字 |
| 活跃设备平台 | 近 30 天使用过、仍在登录状态的设备按平台统计 |

## 4. 用户列表与详情

在 **用户** 页面查看全部用户，新注册的在前，每页 20 位。

- **搜索**：可以按用户名或昵称的任意部分搜索。输入恰好 4 位数字时，也会匹配手机号的末 4 位（为保护用户隐私，不支持更长的号码片段）。
- **手机号**：脱敏显示，例如 `+86 138****5678`。后台不显示完整手机号。

点击用户名打开详情，可以看到：

| 部分 | 内容 |
|---|---|
| 账号 | 用户名、昵称、脱敏手机号、注册时间、最后活跃、已登录的设备数 |
| 设置 | 主题、字号、一周的第一天、新建备忘录的默认提醒 |
| 同步与存储 | 最后一次有数据同步到服务器的时间、服务端同步序号、附件用量与上限 |
| 设备 | 平台、型号、系统版本、App 版本、最后活跃，以及：<br>· 同步：设备是否已同步到最新，没有时显示落后多少条<br>· 状态：是否已登录、能否在本地按时提醒、是否注册了推送 |

**常见排查**：

- **收不到备忘录提醒**：看设备的状态。
  - 没有"本地提醒"：手机没有授予通知或精确闹钟权限，只能依赖推送。
  - 没有"推送"：设备没有注册推送，推送也收不到。
- **另一台手机看不到新内容**：看该设备的"同步"一列。
  - 落后很多：设备可能长期没有联网，或者已退出登录。
  - 已同步：数据已到达该设备，请用户检查筛选条件。

## 5. 审计日志

**审计日志** 页面记录所有管理员的操作，新的在前：

| 操作 | 说明 |
|---|---|
| 登录、登录失败、退出 | 登录失败会注明原因：用户名不存在、密码错误、账号已锁定、账号已停用 |
| 查看仪表盘、查看用户列表、查看用户详情、查看审计日志、查看管理员列表 | 用户列表会记下搜索词和页码，用户详情会记下用户 ID |
| 修改密码 | 修改自己的密码 |
| 新建管理员、修改管理员、重置管理员密码 | 会记下对象和修改前后的内容（角色、是否停用）；在服务器命令行上执行的，操作人显示为"(命令行)" |

可以按操作类型和日期范围筛选。审计日志只能查看，任何人都不能修改或删除。

- 登录失败时输入了不合规的用户名（例如把密码误输进了用户名框），用户名记为"(无效用户名)"，不保存原文。
- 查看类操作必须先写入审计日志才会返回数据；如果审计日志写入失败，页面会提示出错。

## 6. 管理员账号管理

**管理员** 页面只对超级管理员显示。

| 角色 | 权限 |
|---|---|
| 超级管理员 | 查看全部页面，并且可以管理管理员账号 |
| 只读管理员 | 查看仪表盘、用户、审计日志；不能管理管理员账号 |

- **新建管理员**：填写用户名、角色和初始密码。对方第一次登录时必须修改密码。
- **修改角色**：在角色下拉框中选择。
- **停用 / 启用**：停用后对方立即退出登录，并且不能再登录。
- **重置密码**：对方立即退出登录，下次登录时必须修改密码。
- **限制**：
  - 不能修改自己的角色或停用自己。
  - 至少要保留一个启用的超级管理员。

## 7. 部署说明

- 管理后台是静态页面，生产环境由 Caddy 与接口部署在同一域名下（v0.9.0）。登录状态依赖同一域名下的 Cookie。
- 验收时可以在本机运行，接口经 SSH 隧道转发：
  ```bash
  # 先建立到服务器 8080 端口的 SSH 隧道
  cd apps/admin-web
  pnpm build && pnpm preview   # 打开 http://localhost:4173
  ```
