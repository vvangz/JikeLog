# 2026-10-14 · v1.1.0 · Windows 客户端

## 目标

需求要求开发 Windows 与 Android 客户端，先做 Android。v1.0.0 之后开始 Windows 版：与 Android 共用同一套 Flutter 代码。设计见 [ADR-013](../架构/ADR/ADR-013-Windows客户端.md)。

与用户确认的做法：

- **分发**：MSIX + 自签名证书。只有带包标识的应用能取消已排定的 Windows 通知，提醒依赖这一点。用户第一次安装前导入一次证书。
- **富文本编辑器**：如果 Windows 上的 WebView2 方案验证不通过，先只提供 Markdown。

## 完成项

### 平台与按平台开关的功能

- `flutter create --platforms=windows`。窗口标题"即刻日志"，默认 1280×800，最小 400×560。
- `PlatformFeatures`：集中描述各平台能用的功能，通过 Riverpod 提供。`flutter test` 中固定为 Android，使本机（Windows）与 CI（Linux）上的测试行为一致；测试 Windows 行为时覆盖。
- Windows 上关闭：
  - 系统日历：设置页不显示开关；
  - 极光推送；
  - 富文本编辑器：笔记用 Markdown 打开，不改保存的格式，新建的笔记为 Markdown。
- 时区：C++ 运行器实现与 Android 同名的 `jikelog/device` 通道，用 `Windows.Globalization` 读取 IANA 时区，Dart 代码不变。
- 设备信息：上报"Windows PC"与系统版本。不上报计算机名，它常含真实姓名，而设备型号会显示在管理后台。

### 提醒

- Windows 通知（Toast）：应用标识与激活器 GUID 初始化。激活器 GUID 必须与 MSIX 清单一致，由测试保证。
- Windows 没有运行时授权，权限视为已允许。
- "只取消待发通知"在 Windows 上未实现，改为取消全部通知。
- 未打包运行时，读取待发列表或取消失败不再中断提醒排定。

### 附件、音频与导出

- **打开附件**：附件在本机以 ID 命名、没有扩展名。打开时：
  - 复制一份以原文件名命名的副本，文件名经过清理，并写入 Mark-of-the-Web；
  - 只有允许列表中的类型交给默认应用打开，其余只打开所在文件夹；
  - 副本一小时后清理，退出登录时全部删除；
  - 附件 ID 用作文件名前先确认是 UUID。
- **音频**：Windows 上改用 `audioplayers`。播放结束后保留音源；暂停时拖动进度也会更新位置；时长在加载后不可得时等待第一次通知。
- **导出**：选择文件夹后流式下载到那里。文件名只取最后一段；重名时加序号；先写 `.part`，完成后改名，失败时删除。写入失败单独提示"无法写入所选文件夹"。

### 桌面交互

- **快捷键**：Ctrl+F 搜索，Ctrl+N 在当前模块新建，由应用外壳统一处理。
  - 子页面、对话框和底部面板打开时不处理；
  - 排除 Ctrl+Alt（Windows 上 AltGr 会同时报告两者）；
  - 1 秒内不重复新建。
- 各模块的新建操作提取为 `createWorklog`、`createNote`、`createMemo`。

### 应用图标

- 发现 Android 版仍是 Flutter 默认图标。新增 `scripts/gen-app-icons.py`，按管理后台的 logo 生成咖色底、奶油白线条的图标：Android 各密度 PNG、Windows 的 `app_icon.ico`，以及 MSIX 用的 512px PNG。Android 部分单独提交为 PR #23，以便赶上 v1.0.0。

### 打包与发布

- `msix_config`：包标识 `JikeLog.App`，发布者 `CN=JikeLog`，声明 `internetClient` 与 `microphone`，配置通知激活器。
- 自签名代码签名证书：RSA 3072，有效期 10 年，用 OpenSSL 生成，不经过系统证书存储。
  - 私钥（PFX）和密码只放在 `windows-signing` 环境，该环境只允许 `main`。
  - 公钥 `.cer` 放在 `deploy/windows/`，并随每个 Release 发布。
- `release-windows.yml`，与 APK 一样分两个任务：
  - **构建任务**：没有密钥，确认标签在 `main` 上，构建并打包未签名的 MSIX，输出其 SHA-256。
  - **签名任务**：不检出代码，核对收到的安装包与该校验值一致；把 PFX 导入证书存储后按指纹签名，时间戳走 HTTPS；核对签名者的 SHA-1；上传。
- `release-apk.yml` 同样加上产物校验值核对；两个发布工作流的 Action 都固定到提交 SHA。
- CI 新增"Windows 客户端"任务：构建 Windows 版并打包 MSIX（不签名）。

## 问题与解决

| 问题 | 原因 | 解决 |
|---|---|---|
| CI 中 `just_audio_windows` 编译失败（STL1011） | 使用已废弃的 `<experimental/coroutine>`，新版 MSVC 拒绝编译；该包已无人维护 | 改用 `audioplayers` |
| 运行器编译失败（同为 STL1011） | C++/WinRT 在 C++17 下退回 experimental coroutine | 运行器改用 C++20 编译 |
| `flutter create` 顺带升级了多个依赖 | 未锁定的 `pub get` | 还原 `pubspec.lock`，只用 `pub add` 增加需要的包 |
| Windows 模板文件为 CRLF | `flutter create` 在 Windows 上生成 | 统一转为 LF（仓库约定） |
| Git Bash 把 `/CN=JikeLog` 改写为 Windows 路径 | MSYS 路径转换 | 生成证书时设 `MSYS_NO_PATHCONV=1` |
| 本机无法构建 Windows 版 | 未安装 Visual Studio C++ 组件、未开开发者模式 | Windows 编译由 CI 验证；请用户安装后本机验收 |

## 审查记录

通用、安全、Flutter 三个审查都没有 CRITICAL。

| 级别 | 问题 | 处理 |
|---|---|---|
| HIGH（安全） | 附件在本机没有扩展名，按扩展名拦截可执行文件的逻辑实际不会生效；拦截列表也不完整 | 改为以原文件名复制副本，写入 Mark-of-the-Web，采用允许列表 |
| HIGH（安全） | 签名任务直接签名收到的产物 | 构建任务输出 SHA-256，签名任务核对；Action 固定到提交 SHA |
| MEDIUM（安全） | 附件 ID 未校验就用作文件名 | 校验为 UUID |
| MEDIUM（安全） | 导出文件名未限制 | 只取最后一段 |
| MEDIUM（安全） | 证书信任指引不够 | 补充 SHA-256 指纹、从仓库再核对、私钥泄露时如何删除证书 |
| MEDIUM（通用） | 底部面板打开时 Ctrl+N 仍会新建 | 外壳内导航器还有页面时不处理 |
| MEDIUM（Flutter） | Ctrl+N 可能重复新建；AltGr 会触发快捷键 | 1 秒内不重复；排除 Ctrl+Alt |
| MEDIUM（Flutter） | `DesktopPlayer` 与 `PluginPlayer` 行为不一致 | 保留音源、暂停时拖动更新位置、等待时长 |
| MEDIUM（Flutter） | 笔记格式规则散落三处 | 集中为 `newNoteFormat`、`editorFormatFor` |
| 可能（通用） | 未打包运行时读取待发通知可能抛错，中断提醒排定 | Windows 上读取与取消失败时记录日志后继续 |
| LOW | `signtool` 命令行带密码；时间戳用 HTTP；上传通配；签名者不符时信息不足 | 导入证书存储后按指纹签名；HTTPS；只上传指定文件；输出签名状态 |
| LOW | 计算机名可能含真实姓名 | 设备型号改为"Windows PC" |
| LOW | 文档注释位置、平台识别、导出删除临时文件出错时掩盖原错误 | 一并修复 |
| LOW（未处理） | `windows-signing` 不要求审批 | `main` 未设保护，有写权限即可修改发布流程，审批不增加实质保护；仓库只有一位维护者（见 ADR-013） |
