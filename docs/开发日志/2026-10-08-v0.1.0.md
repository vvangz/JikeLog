# 2026-10-08 · v0.1.0 · M0 基础设施

## 目标

搭好 monorepo 和三端工程骨架，并接通工程规范与 CI：设计令牌、接口契约与代码生成、本地开发环境、文档体系。后续里程碑都在这个骨架上做纵向功能开发。

## 完成项

### 仓库与规范
- monorepo 结构：`apps/mobile`、`apps/admin-web`、`server`、`packages/design-tokens`、`deploy`、`scripts`、`docs`
- pnpm workspace；lefthook Git 钩子：commitlint、gitleaks、gofmt、eslint、dart format、设计令牌测试
- Conventional Commits，规则见 `commitlint.config.mjs`；SemVer 版本号与 CHANGELOG 由 Release Please 维护，各端版本行通过 `x-release-please-version` 注释同步更新
- 分支模型、提交规范、发布流程、安全约定见 `CONTRIBUTING.md`
- GitHub：CI 工作流（密钥扫描 / Go / 设计令牌与管理后台 / Flutter）、Release Please、Dependabot、PR 与 Issue 模板、CODEOWNERS

### 设计令牌（`packages/design-tokens`）
- 色板：咖色、沙色（暖灰）、绿、琥珀、红、蓝；浅色/深色两套语义色共 30 个字段，两套字段完全一致
- 共享令牌：字体族、字号、字重、行高、间距、圆角、动效时长、响应式断点
- 用 Style Dictionary 5.6 解析引用，再由自定义生成器输出 Dart（`JkColorTokens` / `JkTokens`）、CSS 变量和 TS 常量
- **自动校验 WCAG 对比度**：正文 ≥ 7、辅助文字 ≥ 4.5、状态色上的文字 ≥ 4.5、状态色与界面元素 ≥ 3。首版色板一次通过

### 服务端（`server`）
- `api/openapi.yaml` 作为契约，oapi-codegen 2.8 生成 Gin 严格服务端桩
- 统一响应信封 `{success, data, error, meta, requestId}`；404、405、panic、请求解析失败也返回同样的信封；5xx 不泄露内部错误
- 请求 ID：沿用合法的上游 `X-Request-ID`（`[A-Za-z0-9_-]{1,64}`），否则生成 UUIDv7
- 访问日志只记录路径，不记录查询串
- `/healthz` 存活探针、`/readyz` 就绪探针（并发检查依赖，单项超时；对外只返回 `unavailable` / `timeout`）、`/api/v1/system/info`
- 配置：环境变量统一加 `JIKELOG_` 前缀，启动时校验，非法时列出全部错误后拒绝启动；默认不信任 `X-Forwarded-For`
- 优雅关闭：收到 SIGTERM 后在 `SHUTDOWN_TIMEOUT` 内排空连接
- 多阶段 Dockerfile：运行时为 alpine + 非 root 用户，带 HEALTHCHECK
- golangci-lint v2 配置：启用 gosec、errorlint、revive 等

### 管理后台（`apps/admin-web`）
- React 19.3 + Ant Design 6.6 + Vite 8.3 + TypeScript 6.0 + Vitest 5
- 设计令牌映射为 AntD 主题（含暗色算法）；支持浅色/深色/跟随系统，持久化到 localStorage（隐私模式下不可用时也不报错），并同步到 `<html data-theme>`
- 外壳原型：左上角品牌图标点击后，侧栏自上而下展开（上部是模块入口，下部是设置、账号）；手机宽度下侧栏以浮层显示；遵循"减少动态效果"
- `openapi-fetch` 类型化客户端，类型由 openapi.yaml 生成

### 移动端（`apps/mobile`）
- Flutter 3.47.6，包名 `com.jikelog.app`，minSdk 26，应用名"即刻日志"
- `AppTheme.light()/dark()`：全部取值来自令牌；Space Grotesk 为主字体，MiSans 为中文回退；`JkColors` ThemeExtension 暴露状态色等扩展令牌
- `JkLogo` 品牌标志，与 Web 端 SVG 同一造型
- 占位首页（v0.2.0 起替换为导航外壳）

### 开发环境与文档
- `deploy/docker-compose.dev.yml`：PostgreSQL 17、Redis 7.4、RustFS（S3 兼容）。端口只绑定 127.0.0.1，密码从 `.env` 读取并强制必填
- `scripts/fetch-fonts.sh`：从官方渠道下载字体，复制到两端
- 文档：README、架构总览、ADR-001 技术选型、ADR-002 字体分发、设计规范、本地开发环境、使用说明目录、管理员手册框架

## 关键决策

| 决策 | 原因 |
|---|---|
| 字体不入库，由脚本下载（ADR-002） | 核对 MiSans 许可协议后确认：可以打包进 App，但禁止单独再分发字体文件，而公开仓库属于再分发 |
| 本地对象存储用 RustFS 替代 MinIO | MinIO 已不在 Docker Hub 发布社区版镜像；生产仍用阿里云 OSS |
| React 19 / AntD 6 / PostgreSQL 17（计划中写的是 18 / 5 / 16） | 立项时的稳定版本已升级，详见 ADR-001 |
| TypeScript 6.0 而不是 7.0 | typescript-eslint 8.71 目前只支持 TS < 6.1 |
| Go 模块要求 1.27.1 | gin 1.12 / oapi-codegen 2.8 要求 Go ≥ 1.25；本机为 1.23.3，依靠 `GOTOOLCHAIN=auto` 自动下载 |
| 各模块 Handler 通过类型别名嵌入 `server.API` | 各模块的类型都叫 `Handler`，直接嵌入会产生字段名冲突 |

## 问题与解决

1. **`go tool oapi-codegen` 报 "executable file not found"**：起初以为是 Go 在 Windows 上的缓存问题。排查后发现是本机全局 `go env` 设置了 `GOOS=linux`，工具被编译成了 Linux 二进制。没有修改全局配置，而是让 `scripts/gen-api.sh` 和 `scripts/go-coverage.sh` 在构建本机工具和测试时显式使用宿主平台的 GOOS/GOARCH，并写进了 CONTRIBUTING 和 FAQ
2. **golangci-lint 报 "Go language version (go1.26) … lower than targeted (1.27.1)"**：`go install` 时按 golangci-lint 自身的 go.mod 选了旧工具链。改为用 `GOTOOLCHAIN=go1.27.1` 构建
3. **Vitest 用例之间 DOM 残留**：没有启用 globals 时，Testing Library 不会自动清理。在 setup 中显式加入 `afterEach(cleanup)`
4. **MiSans 官网下载链接由 JS 生成**：从前端代码中解析出真实地址 `https://hyperos.mi.com/font-download/MiSans.zip`（约 228MB，包含 ttf/otf/woff/woff2/可变字体）

## 审查记录

两个审查代理分别做了代码审查和安全审查。结论：0 个 CRITICAL；HIGH 已全部修复；MEDIUM 除下表注明的外已全部修复。

### 安全审查（0 CRITICAL / 0 HIGH / 5 MEDIUM）

| 发现 | 处理 |
|---|---|
| 公开仓库卫生：没有密钥、个人信息或字体文件进入提交 | ✅ 确认 |
| Git 提交邮箱会公开 | ⚠️ 已提醒，由仓库所有者决定是否改用 GitHub noreply 邮箱 |
| CI 下载 gitleaks 时没有校验 | ✅ 固定 SHA256 并强制 HTTPS |
| 第三方 action 只用了可变标签 | ✅ 改为固定到提交 SHA（逐个独立核实）；发布工作流的写权限只放在 job 级别 |
| `pubspec.lock` 记录的是镜像地址 | ✅ 保留镜像地址（改为 pub.dev 会导致国内开发环境反复改写锁文件），CI 使用同一镜像并加 `--enforce-lockfile`，靠锁文件中的 sha256 保证完整性 |
| CI 没有漏洞扫描 | ✅ 新增 govulncheck 和 pnpm audit。首次运行就发现 **GO-2026-5676**（gin 间接依赖的 quic-go 存在 HTTP/3 内存耗尽问题，代码可达），已升级 quic-go 0.59.1，同时升级 x/crypto、x/text、kin-openapi |
| 低危加固 | ✅ 字体包 SHA256 校验；安全响应头；请求头上限 64KB；生产环境禁止信任 0 前缀网段；默认只监听本机；镜像以数字 UID 运行；Android 禁止备份和设备迁移；新增 SECURITY.md |

### 代码审查（0 CRITICAL / 1 HIGH / 8 MEDIUM / 17 LOW）

| 发现 | 处理 |
|---|---|
| **H1** 就绪检查的超时只在检查项配合时生效，检查项 panic 会让进程崩溃 | ✅ 每项检查在独立 goroutine 中运行，用 select 强制超时，并用 recover 隔离 panic；检查使用与请求无关的 context，避免持有会被回收的 `*gin.Context` |
| M1 请求取消信号传不到处理器 | ✅ `ContextWithFallback = true`，并加测试 |
| M2 探针不支持 HEAD（阿里云 CLB 默认用 HEAD） | ✅ 为 `/healthz`、`/readyz` 注册 HEAD |
| M3 契约中没有声明错误响应 | ✅ 每个接口加 `default: Error`；`data` 和 `error` 设为必填，TS 端可以拿到类型化的错误 |
| M4 Release Please 与分支模型冲突；用 GITHUB_TOKEN 创建的 PR 不触发 CI | ✅ 重写发版流程；支持配置 `RELEASE_PLEASE_TOKEN`；加 `version.txt`；openapi 版本号也纳入同步；关闭内嵌 spec，避免发版后生成代码不一致 |

| M7 Flutter 覆盖率统计漏掉没有被测试引用的文件 | ✅ 新增 `scripts/flutter-coverage.sh`，生成引用 lib 下全部文件的辅助测试 |

| LOW（已修） | 关闭宽限期改为 8s（小于 Docker 默认的 10s）；关闭超时后强制 Close；第二次 Ctrl+C 可立即退出；可信代理去空白并校验 CIDR；`ErrAbortHandler` 继续向上抛；ColorScheme 补齐 secondaryContainer/tertiary；缓存 ThemeData，JkColors 实现相等性；Dependabot 覆盖所有 workspace 包；令牌改为引用色板，并校验字段一致性和字重 |
