# 2026-10-14 · v1.2.0 · 官网

## 目标

Android 与 Windows 两个客户端发布后，需要一个符合常规的软件官网：产品介绍、两个平台的下载、使用教程、更新日志、隐私政策与用户协议。设计见 [ADR-014](../架构/ADR/ADR-014-官网与安装包下载.md)。

与用户确认的做法：

- **下载地址**：安装包放在自己的服务器上，GitHub Release 作为备用（国内访问 GitHub 不稳定）。
- **法律页面**：按实际的数据处理起草隐私政策与用户协议，标为草稿，由用户审定。
- **外观**：以美观为主，不要求与 App 的主题色一致。

## 完成项

### 官网（`apps/site`，VitePress）

- **首页**：
  - 首屏：标题与说明、两个下载按钮，右侧是用 HTML/CSS 绘制的产品示意（电脑窗口中的工作日志、手机上的提醒、记账与待办）；
  - 四个模块的卡片，链接到对应教程；
  - 六项细节（同步、离线、搜索、导出、主题、快捷键）；
  - 安全与隐私（深色区块，链接到隐私政策）；
  - 两个平台、常见问题（6 条）、号召栏。
- **下载页**：读取 `/download/latest.json` 显示版本、发布日期、大小与 SHA-256（可一键复制）；Windows 卡片附证书指纹与证书下载；每张卡片有 GitHub 备用链接；读不到清单时引导到 GitHub。下方是两个平台的安装步骤与校验方法。
- **使用教程**：由 `docs/使用说明` 生成，侧栏列出各章，首页是章节卡片（简介取自使用说明 README 的章节表）。
- **更新日志**：由 `docs/发布说明` 生成，版本从新到旧。
- **隐私政策、用户协议**：`docs/法律/` 中的草稿。
- 全站页脚（产品、帮助、关于三栏，版权与 ICP 备案号）、404 页、`sitemap.xml`、`robots.txt`、分享图与图标。
- **配色**：青绿到天蓝的渐变，四个模块各有点缀色；深浅两套主题。放白字的背景（按钮、号召栏）在深色主题下也用深色渐变，保证对比度。
- **适配**：桌面、平板、手机三档布局；窄屏下产品示意只保留电脑窗口。尊重"减少动态效果"的系统设置。
- **中文搜索**：本地搜索改用 `Intl.Segmenter` 分词。

### 文档同步（`lib/docs.mjs`）

- 章节网址在 `GUIDE_SLUGS` 中登记，新章节未登记时构建失败。
- 链接改写：章节之间 → 官网地址；GitHub 风格锚点 → VitePress 风格（数字开头加 `_`）；官网自身的完整地址 → 站内路径；其他仓库文件 → GitHub 链接；代码块不动。
- 使用说明第 1、9 章的下载步骤改为先从官网下载页下载，GitHub 作为备用。

### 安装包下载与部署

- `release-please.yml`：部署等 APK 与 Windows 两个任务完成后再运行（任一失败照常部署）。
- `deploy.yml`：
  - 构建官网（先运行官网测试），页脚的 ICP 备案号取仓库变量 `SITE_ICP`；
  - 从 Release 下载安装包，核对 `.sha256`、APK 签名证书（`apksigner`）与 Windows 证书指纹（`openssl`），生成 `latest.json`；Release 中没有安装包时只给出警告。
- `deploy.sh`：解压 `site.tar.gz` 与 `downloads.tar.gz` 到各自的版本目录并切换 `current`；失败时连同管理后台一起切回；清理时各保留最近 3 个版本。发布包中没有这两个文件时保留服务器上现有的。
- Caddyfile：
  - `/download/*`：安装包作为下载（`Content-Disposition: attachment`、正确的 `Content-Type`、sandbox CSP），`latest.json` 不缓存，不列目录；
  - 其余路径交给官网：地址不带 `.html`，`/assets/` 长期缓存，页面每次校验，找不到时显示官网 404 页；
  - 根路径不再跳转到管理后台。
- `compose.yml`：Caddy 挂载 `site/` 与 `downloads/`。

### 安全

- 官网与管理后台、接口同源，每个页面带严格的 CSP：只允许本站脚本，VitePress 的内联脚本按内容哈希放行（`lib/csp.mjs`，构建时计算）；Caddy 补上 `frame-ancestors 'none'`、`X-Frame-Options: DENY`、`Permissions-Policy`。
- 下载页对 `latest.json` 逐字段校验（版本号、文件名白名单、SHA-256 格式、发布地址必须是 GitHub），不合法的条目丢弃。
- 不加载任何外部资源（字体、统计、CDN）。

### 测试与 CI

- `apps/site/test`：文档同步、链接改写与危险 HTML 检查，下载清单生成与校验（含校验值不符、上传到一半、非法版本号与发布时间、命令行脚本），CSP 生成与未知内联脚本，证书指纹一致性；共 29 个测试，行覆盖率 98%。
- `deploy/production/tests/caddy-smoke.sh`：用真实的 Caddy 镜像加载正式环境的 Caddyfile，检查 17 条路由与响应头。
- `scripts/collect-downloads.sh`、`deploy.sh`、工作流经 shellcheck 与 actionlint 检查。
- CI 的前端任务增加：官网测试与覆盖率、官网构建、Caddyfile 路由检查。

## 问题与解决

| 问题 | 原因 | 解决 |
|---|---|---|
| CI 的 `pnpm audit` 报高危 | VitePress 1.6.4 依赖的 Vite 5 有高危公告 | 改用 VitePress 2.0.0-alpha.20（Vite 8，与仓库其他前端一致） |
| 中文搜索搜不到句中的词 | 默认按空格分词，中文整句成为一个词 | `Intl.Segmenter` 按词切分 |
| 隐私政策初稿中的几处说法与实现不符 | 沿用了 App 内旧文本 | 逐项核对代码后改写，见下方"隐私政策核对" |
| 冒烟测试在 Git Bash 下误报 | `grep -q` 提前退出触发 `pipefail`；Git Bash 的 `grep -iF` 遇到某些输入异常退出 | 改用 bash 自带的字符串匹配 |
| 本机截图检查时页面空白 | 4173 端口被管理后台的预览占用 | 换端口 |

## 隐私政策核对

起草时逐项对照了代码，以下几点与 App 内现有文本（`policy_text.dart`）不同，以新文本为准：

- **附件文件本身不做应用层加密**，只有文件名加密；附件经 10 分钟有效的签名地址访问。
- **极光推送与短信服务没有接入**：Android 安装包含极光推送 SDK，但未配置、不初始化。
- **删除记录是"墓碑"**：删除前的最后版本以密文保存在修订历史中，可以恢复；彻底清除需要注销账号。
- **备份保留最近 6 份（约 84 天）**：注销后，此前备份中的副本在最多约 84 天内随轮换删除。备份同时包含数据库（含包裹后的数据密钥）与主密钥，所以 ADR-006 中"注销后备份里的密文无法再解开"的说法不成立，隐私政策没有采用。
- Windows 版的设备型号统一为"Windows PC"，不读取计算机名。

## 审查记录

通用审查与安全审查都没有 CRITICAL。

| 级别 | 问题 | 处理 |
|---|---|---|
| HIGH（安全） | ADR-006 称"注销后备份里的密文无法解开"，但备份同时含数据库与主密钥 | 更正 ADR-006；隐私政策写明备份在轮换前仍可恢复，并说明运营者在技术上能解密 |
| HIGH（安全） | CSP 对页面里出现的任何内联脚本都放行，混进文档的 `<script>` 会被自动加入白名单 | 只放行固定的两段 VitePress 脚本，其余构建失败；同步文档时拒绝脚本、事件属性、`javascript:` 链接等 |
| HIGH（安全） | 部署时 `APK_CERT_SHA256` 为空则任何证书都能通过；MSIX 只靠同在 Release 中的 `.sha256` | 证书变量为空时失败、整行比对；签名任务输出校验值，经 Release Please 传给部署工作流核对 |
| HIGH（通用） | 法律文本是草稿却会自动上线 | 构建时对含【待填写】的法律文本给出警告（页面上有"草稿"提示）；由你审定后再上线 |
| HIGH（通用） | 重新部署同一版本时先删后解，失败无法回滚；解包在设置回滚之前 | 先解到临时目录再换上，原内容移开、失败时换回，`current` 原子切换；回滚从解包前开始生效；用临时目录模拟了首次、升级、同版本重部署、回滚四种情形 |
| MEDIUM | `always()` 在工作流被取消时也会部署 | 改为 `!cancelled()` |
| MEDIUM | 下载失败被当作"没有安装包"；Release 上传到一半时整个部署失败 | 先列出附件再下载；缺少 `.sha256` 或证书的平台不收录并警告 |
| MEDIUM | 官网构建与持有 SSH 密钥的部署在同一任务中 | 拆成不带 production 环境的"官网与安装包"任务，产物交给部署任务 |
| MEDIUM | Windows 证书指纹比较未统一大小写与冒号；页面上的指纹是写死的 | 两边统一格式；`latest.json` 带证书的 SHA-1，页面优先显示它；测试校验页面常量与使用说明一致 |
| MEDIUM | 隐私政策：上传地址是 15 分钟；附件的类型、大小是明文 | 已改 |
| MEDIUM | 链接改写的边缘情况：页内数字锚点、官网地址后直接跟锚点、坏的百分号转义、预发布版本排序、发布说明目录的 README | 都已处理并补测试 |
| MEDIUM（安全） | 附件的 Content-Type 由上传者声明，同源的 `script-src 'self'` 也包括它们 | 需要先能注入 HTML，官网内容只来自仓库并经过检查；记为后续事项（服务端限制附件类型，或对象存储换子域名） |
| 不成立 | 管理后台没有脚本 CSP | 管理后台的 `index.html` 已有按哈希放行的 meta CSP（v0.8.0） |
| LOW | 404 页可被嵌入；`/admin/assets/` 下不存在的文件被缓存一年；不存在的安装包返回带 APK 类型的网页 | 404 处理中改写响应头，冒烟测试增加 3 项（共 17 项） |
| LOW | 安装包缓存一天；`latest.json` 的发布时间用的是部署时刻；只取白名单文件名；解包后的软链接 | 改为每次校验；取 Release 的发布时间；只下载 5 个固定文件名；解包后删除软链接 |
| LOW | 下载页先显示 GitHub 链接再变成本站链接 | 读取清单前显示"正在获取最新版本…"；不支持脚本时显示 GitHub 链接 |
| LOW | 旧版本没有 `apps/site`，手动重新部署会失败 | 官网任务检测到没有 `apps/site` 时跳过，只部署程序 |

## 遗留事项与下一步

- **需要你完成**：
  - 审定隐私政策与用户协议，填写运营者名称、联系邮箱、生效日期与争议管辖地；
  - 审定后同步 App 内的文本（`policy_text.dart`）并递增 `privacyPolicyVersion`；
  - ICP 备案通过后，在仓库变量中设置 `SITE_ICP`。
- 首个包含官网的版本发布后，检查 `/download/latest.json` 与两个安装包能否下载。
- 使用说明第 10 章"常见问题"待补充；补充后在 `GUIDE_SLUGS` 中登记。
- 附件类型白名单（服务端拒绝 JavaScript、HTML、SVG 等类型），或把对象存储移到独立的子域名（ADR-014 第 4 节"剩余风险"）。
- 若要做到"注销即不可恢复"，须把主密钥移出备份，与备份私钥分开保管（ADR-006 更正）。
