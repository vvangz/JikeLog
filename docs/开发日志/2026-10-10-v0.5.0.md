# 2026-10-10 · v0.5.0 · M4 备忘录 + 日历 + 推送

## 目标

需求 6 和需求 9 的通知部分：

1. 备忘录包含日期时间和备忘内容
2. 支持提前提醒
3. 与日历关联
4. 通知渠道为 App 推送
5. 多设备同步，并且提醒不能重复

## 完成项

### 设计

见 [ADR-008](../架构/ADR/ADR-008-备忘录提醒与日历.md)：

- 备忘录只加密内容；时间和提醒设置是明文，服务端需要据此按时推送。
- 提醒以本地精确闹钟为主，服务端推送补位。去重的规则是：设备能在本地提醒、已同步到这一版备忘录、且提醒时刻在本地闹钟的覆盖范围内时，服务端不推送。
- 服务端调度用 PostgreSQL 表加轮询，不用 asynq（与计划不同）。
- 推送不含备忘内容。
- 系统日历单向写入。

### 服务端（`server`）

- **同步实体 `memo`**：
  - 字段：`content`（加密，可补丁合并）、`at`、`allDay`、`reminders`、`done`。
  - 新增字段类型 `KindTime`（Unix 毫秒，2000–2199 年）和 `KindOffsets`（规范形式的提前分钟列表，最多 5 个，0 到 30 天）。
- **待发提醒表 `memo_reminders`**：
  - 在同步推送的事务内，按备忘录的最新状态逐条更新。
  - 修改时间或提醒、完成、删除时替换或删除对应提醒。已到时尚未发出、且时刻未变的提醒保留。
- **调度器**（`internal/reminder`），运行在 API 进程中，每 10 秒检查一次：
  - 每批领取 20 条（`SKIP LOCKED`），领取期限 5 分钟。
  - 失败重试 3 次。服务停机超过 1 小时的提醒不再补发。
  - 按设备时区分组推送。
- **推送通道**（`internal/platform/pusher`）：
  - 极光 REST API v3。
  - 默认是 `log`，只记录设备数，不调用极光。
  - 推送标识失效时清除。
- **`PUT /api/v1/me/push`**：登记推送标识、时区、本地提醒能力和本地覆盖范围。
  - 标识只能从同一账号的设备，或已下线、会话已过期的设备转移，防止抢占他人的推送。
  - 限流为每台设备每小时 30 次。
  - 设备下线或退出登录时清除标识。
- **配置**：新增 `JIKELOG_PUSH_PROVIDER` 和 `JIKELOG_PUSH_JPUSH_*`，极光地址必须是 https。
- **迁移** `00003_reminders.sql`：`devices` 新增推送相关列，新增 `memo_reminders` 表。

### 移动端（`apps/mobile`）

- **备忘录**（`features/memos`）：
  - 列表：逾期在前，其余按日期分组，已完成折叠；每分钟刷新一次分组。
  - 编辑页：
    - 新建时填写内容后才保存。
    - 内容 1 秒防抖自动保存，保存按顺序进行。
    - 时间、全天、提醒立即保存。
    - 提醒可选常用提前量，也可自定义。
    - 远端修改与本地输入合并。
  - 日历：
    - 月、两周、周视图，标记备忘与工作日志。
    - 选中日期列出当天内容，并可在该日新建。
    - 手机上日历与当天内容同在一个滚动区域；宽屏时左右并排。
- **提醒**（`features/reminders`）：
  - 本地通知：
    - 精确闹钟，只排最近 64 条，多删少补。
    - 单条失败不影响其他。
    - 锁屏隐藏内容。
    - 点按通知打开对应备忘。
  - 推送：
    - 极光 AppKey 由构建参数注入。
    - 同意隐私政策后才启动，并关闭与推送无关的功能。
  - 协调器：
    - 按登录和隐私同意状态启停。
    - 回到前台时检查权限和时区，并重新登记。
    - 本地覆盖范围变化时重新登记。
    - 退出登录后清除登记记录。
  - 系统日历：
    - 在设置中按设备开启，开启前说明会以明文写入。
    - 按账号记录日历的归属。
    - 关闭或退出登录时删除日历。
- **设置**：显示提醒权限状态并可一键开启；新增"备忘录同步到系统日历"开关。
- **隐私政策**：写明推送 SDK、通知、日历权限，以及写入系统日历的内容。版本升到 2，老用户需要重新同意。
- **本地库升到 v3**：新增系统日历对应关系表。
- **Android**：
  - 新增权限：通知、精确闹钟、开机广播、日历。
  - 移除极光 SDK 的定位、电话状态、应用列表、写外部存储权限，以及 `InitProvider`。
  - 关闭 Flutter 深链接，避免点按厂商通道的通知后白屏。

## 关键决策

| 决策 | 理由 |
|---|---|
| 服务端调度用 PostgreSQL 表，不用 asynq | 待发提醒与备忘录写入在同一事务内完成，修改、完成、删除走同一条代码路径；用 `SKIP LOCKED` 加领取期限，多实例部署也安全；不需要新增 worker 进程 |
| 推送不含备忘内容 | 推送经过第三方通道；内容在本机解密后查看 |
| 设备上报本地闹钟的覆盖范围 | 本地只排最近 64 条。不上报的话，第 65 条以后的提醒服务端以为本地会响，本地却没排，提醒会丢 |
| 推送标识不能抢占其他账号在用的设备 | 只知道对方标识的用户也截不走对方的提醒；同一部手机换账号时，旧会话已下线或过期，可以转移 |
| 系统日历写入前明确告知 | 备忘内容在 App 内加密，写入系统日历后成为明文，其他有日历权限的应用可读 |
| 全天备忘按创建设备时区的 9:00 存为绝对时刻 | 实现简单，服务端可以直接推送。跨时区时日期可能偏移一天，作为已知限制记录（产品面向国内用户） |

## 问题与解决

| 问题 | 解决 |
|---|---|
| 首次构建卡住 40 分钟 | 各插件的构建脚本分别从 Maven Central 下载旧版 AGP 和 Kotlin 编译器。去掉 flutter_timezone 后，下载量大幅减少 |
| `checkDebugAarMetadata` 失败 | flutter_local_notifications 需要开启 core library desugaring |
| 极光 SDK 在用户同意前自行初始化，并带入大量权限 | 清单中用 `tools:node="remove"` 移除 `InitProvider` 和无关权限；Dart 侧同意后才调用 `setAuth(true)` 和 `setup` |
| Windows 上用 Python 修改文件时 LF 变成 CRLF，gofmt 报出大量文件 | 写文件时加 `newline=''` |
| 组件测试中用 `router.go` 切到账号页后，点退出登录不弹确认框 | 与实际使用无关（用户经侧栏进入），测试改为经侧栏进入 |

## 审查记录

三个审查（通用、Flutter、安全）都没有 CRITICAL。HIGH 和 MEDIUM 已全部修复并补了测试，部分 LOW 一并处理。

| 级别 | 问题 | 处理 |
|---|---|---|
| HIGH | 本地只排最近 64 条，服务端却认为设备会本地提醒全部提醒，之后的提醒会丢失 | 设备上报覆盖范围，超出的由服务端推送；有提醒排定失败时缩小覆盖范围 |
| HIGH | 退出后重新登录时，登记签名与上次相同，跳过登记，新会话收不到推送 | 退出登录时清除登记记录 |
| HIGH | 取推送标识最多等 15 秒，期间排队的退出登录被挡住；协调器销毁后仍可能继续执行 | 登记不再阻塞；用启停代数终止过期的异步操作；回到前台的错误被捕获 |
| MEDIUM | 推送标识可被其他账号抢占 | 只能从同账号、已下线或会话过期的设备转移，否则返回 409；登记限流 |
| MEDIUM | 写入系统日历的内容是明文，隐私政策没有说明 | 开启前弹窗说明，隐私政策补充 |
| MEDIUM | 领取期限可能短于整批发送时间，导致其他实例重复推送 | 每批 20 条、期限 5 分钟，期限将尽时停止发送本批剩余提醒 |
| MEDIUM | 到时未发的提醒，在修改备忘内容后被删除 | 逐条更新，保留时刻未变的提醒 |
| MEDIUM | 多个时区分组中有一组失败时，已成功的组会再收到一次 | 记录为可接受（ADR-008） |
| MEDIUM | 系统日历把任何平台错误当作"不存在"，重复创建事件 | 只把 notFound 当作不存在，其他错误保留对应关系，下次重试 |
| MEDIUM | 没有备忘时，每次同步都重建系统日历 | 按账号记录日历归属，不再根据对应关系是否为空推断 |
| MEDIUM | 一条提醒排定失败，后面的全部跳过 | 逐条捕获错误 |
| MEDIUM | 编辑页写入前就记为已保存，失败后不再重试；新建过程中再次保存会建出两条 | 写入成功才记为已保存；保存串行进行；失败时提示 |
| MEDIUM | 远端修改替换整个文本，光标跳到开头 | 按公共前缀保留光标位置；只移动光标不触发保存 |
| MEDIUM | 编辑某条备忘时点按它的通知，会再打开一个编辑页；启动通知在重新登录后再次打开 | 当前已在该页时不再打开；启动通知只处理一次 |
| MEDIUM | 手机上当天内容只能占用日历下方剩余的高度，矮屏或大字号时几乎看不到 | 日历与当天内容同在一个滚动区域 |
| MEDIUM | 列表一次构建全部条目；页面开着时到点的备忘不会移入"已逾期" | 按需构建；每分钟刷新分组 |
| MEDIUM | 全天备忘跨时区时日期偏移 | 记录为已知限制（ADR-008、使用说明） |
| LOW（一并处理） | 锁屏显示备忘内容；通知中的 ID 未校验格式；超过尝试次数仍会再发一次；失效标识不清除；复选框没有读屏标签；完成和删除失败没有提示；全天事件跨夏令时结束日错误；payload 摘要用了不稳定的哈希；换时区时不必要地取消全部闹钟 | 全部修复 |
