## 目标

实施计划中 M8 的内容：阿里云部署（HTTPS、GitHub Actions 部署）、14 天备份与恢复演练、安全审查、k6 压测、性能调优。

- 沿用现有 ECS 单机自托管，不使用 RDS、ACR、KMS。
- `www.pingvv.top` 备案中：正式域名的部署全部做好，备案通过前继续用 SSH 隧道验收。
- 短信与推送暂不接入，只开放用户名加密码登录，留好开关。

## 完成项

### 部署（`deploy/production`、`.github/workflows/deploy.yml`）

- **一台服务器、一个 Compose 项目**：caddy、api、postgres、redis、objectstore、backup。PostgreSQL 与 Redis 按 1.7G 内存限制了缓存与连接数，日志按大小轮转。
- **一个域名承载全部入口**（Caddy）：
  - `/api/*` 转发到接口（含 WebSocket）。
  - `/admin/*` 是管理后台静态文件。单页应用的路由回到 `index.html`；带哈希的资源长期缓存，找不到时返回 404。
  - `/<存储桶>/*` 是附件的预签名上传与下载，只允许 GET、PUT、HEAD。签名包含主机名，因此 Caddy 原样转发 Host。响应一律作为下载处理（`Content-Disposition: attachment`、CSP `sandbox`）。
  - 证书只向 Let's Encrypt 申请；开启 HSTS；不带 www 的域名跳转过来。
- **配置**：
  - `init-env.sh` 生成 `.env` 与 `backup.env`（权限 600），所有机密都是随机值，可以重复执行。
  - 异地 OSS 的 AccessKey 单独放在 `backup.env`，接口服务读不到。
- **发布流程**：
  - Release Please 发布新版本后自动部署，也可以手动运行。
  - CI 构建 API 镜像、备份镜像和管理后台。服务器无法访问 Docker Hub，所以 CI 先检查服务器缺少哪些第三方镜像，一并打包，经 SSH 上传。
  - `deploy.sh` 依次执行：校验版本与必填配置 → 部署前备份数据库 → 载入镜像、更新配置 → 迁移 → 启动 → 就绪检查。
  - 失败时自动切回上一个版本的镜像、配置和管理后台。
  - 成功后发布包、管理后台和镜像各保留 3 个版本。
- **管理后台**：按 `/admin/` 路径构建，路由的 basename 去掉结尾斜杠。

### 14 天加密备份（`deploy/backup`）

- **调度**：backup 容器每天 03:30 检查一次，距上次成功备份满 14 天就执行。按秒比较，留 2 小时余量，保证间隔是 14 天而不是 15 天。
- **内容**：数据库全量、附件存储桶、`.env`（含本地主密钥，没有它数据库中的敏感字段解不开），以及各表行数。行数从导出文件中统计，与导出是同一个快照。
- **加密**：先打包、再用 age 公钥加密，服务器上没有私钥。
- **存放**：
  - 本地保留 6 份。
  - 同时上传到另一地域的 OSS。服务器上的 AccessKey 只能写入，旧备份由存储桶的生命周期规则删除。
- **监控**：结果写入 `status.json`，`check-backup.sh` 用于监控。
- **恢复**：`restore.sh` 默认做演练，恢复到临时数据库并核对行数与附件数；加 `--production` 才覆盖正式数据。

### App 正式版锁定 CA（`apps/mobile/lib/core/net`）

- 正式版连接 HTTPS 服务器时只信任 Let's Encrypt 的两个根证书（ISRG Root X1、X2）。设备上即使装了抓包工具或企业代理的根证书，也无法解密 App 的流量。
- 接口（含刷新令牌）、附件上传与下载、导出下载、WebSocket 都经由 `tlsPolicyProvider`，没有遗漏的网络出口。
- 调试构建与 HTTP 地址（隧道验收）使用系统信任库。`--dart-define=JIKELOG_PIN_CA=false` 可以关闭锁定，排查时使用。

### 性能调优（`server/internal/syncer`）

推送原先每条变更要查询 3 次数据库：读取并锁定记录、检查 ID 是否被其他账号占用、插入。现在改为：

- 整批的记录和 ID 占用各用一次查询读出（`ListRecordsForUpdate`、`ListForeignRecordIDs`）。
- 新记录的插入排队，通过 pgx 管道一次发出（`InsertRecordBatch`）。
- 同一 ID 在一批中再次出现时，先发出排队的插入，再逐条查询。
- 预读之后另一个账号抢先插入了同一 ID：这一条报告 ID 冲突，序号留空，不影响增量拉取。

本机推送 100 条从 62ms 降到 21ms（平均），推送 500 条（5 次）的 p95 从 351ms 降到 130ms。

### 压测（`deploy/loadtest`）

- k6 脚本覆盖三个场景：常用读接口、推送并拉取 500 条、实时通知。工作日志的敏感字段与 App 一样加密。
- 压测环境是独立的 Compose 项目，镜像与资源参数与正式环境相同，用完连同数据删除。
- 结果见下文"测试结果"，步骤见[《压测》](../部署运维/压测.md)。

## 关键决策

| 决策 | 理由 |
|---|---|
| 单机自托管，不用 RDS、ACR、KMS | 用户选择，每月节省数百元。以后迁移只需 `pg_dump` 与对象存储复制 |
| 对象存储与接口共用一个域名 | 预签名地址的签名含主机名；不需要额外的子域名与证书 |
| 镜像在 CI 构建后直接上传 | 服务器访问不了 Docker Hub，也不必维护镜像仓库 |
| 按"距上次成功满 14 天"调度，不用 cron 的日期步长 | cron 的步长到月底会重置，间隔不总是 14 天 |
| 备份包含 `.env` 并用 age 公钥加密 | 没有主密钥，数据库备份解不开；服务器上只有公钥，被攻破也解不开备份 |
| OSS 的 AccessKey 只能写入，旧备份由生命周期规则删除 | 服务器被攻破时，异地备份不会被删除或覆盖 |
| 只信任 Let's Encrypt 的根证书，而不是锁定服务器证书 | 证书每 60~90 天更换一次，锁定证书需要频繁发版；锁定 CA 只在 Let's Encrypt 更换根证书时才需要发版 |
| 推送改为整批预读、管道插入，不改接口 | 不需要修改 App；单次推送 100 条的上限保留 |

## 问题与解决

| 问题 | 解决 |
|---|---|
| k6 没有 X25519，无法像 App 一样握手 | `e2e-keys.sh` 用 OpenSSL 预先生成密钥对并算出会话密钥，k6 只做 AES-GCM |
| 一页最多返回 100 条，拉取 500 条的检查失败 | 服务端为限制内存，每页最多读 100 行；压测改为分页拉取，按总耗时计算 |
| 同一账号的推送超过每分钟 120 次的限制 | 压测按迭代序号轮流使用 8 个账号 |
| 服务器上 k6 写不了结果文件 | k6 容器以非 root 用户运行，`run.sh` 放开结果目录的权限 |
| 本机构建备份镜像时，Alpine 软件源解析失败 | 增加 `APK_MIRROR` 构建参数，本机构建用阿里云镜像；CI 不受影响 |
| 批量插入后，附件（服务端创建的记录）没有写入 | `WriteServerRecord` 也使用这个写入器，但不会发出排队的插入。批量模式只在推送中开启 |
| Git Bash 中 `MSYS_NO_PATHCONV` 让 OpenSSL 找不到临时文件；`tar` 把 `C:` 当成远程主机 | 只在调用 Docker 时关闭路径转换；打包时使用 `/c/...` 路径 |

### 压测

服务器（2 核 1.7G ECS，k6 在同一台机器上）：

| 指标 | 目标 | 结果 |
|---|---|---|
| 读接口 p95 | < 100ms | 11.8ms |
| 推送 500 条 p95（5 次合计） | < 200ms | **357ms**（中位数 262ms）；读接口降到每秒 1 组时为 242ms |
| 拉取 500 条 p95（5 页合计） | < 200ms | 115ms |
| 实时通知 p95 | < 1s | 55ms |
| 错误率 | < 1% | 0%（2 分钟 12,312 个请求） |

服务器上推送 500 条的 p95 没有达标。每次推送的耗时主要在 PostgreSQL 写入 100 行与提交上，Go 代码只占约 13ms。另外 k6 与服务在同一台 2 核机器上，k6 每轮还要加密 500 条记录，结果偏保守。可选的改进见[《压测》](../部署运维/压测.md)。

## 审查记录

三个审查（通用、安全、Flutter）都没有 CRITICAL。HIGH 与 MEDIUM 已全部修复，大部分 LOW 一并处理。

| 级别 | 问题 | 处理 |
|---|---|---|
| HIGH（安全） | 手动部署时输入的版本号直接拼进 shell 与 SSH 命令，可以在服务器上以 root 执行任意命令 | 输入经环境变量传入，按语义化版本校验；`deploy.sh` 再校验一次 |
| HIGH（Flutter） | 证书锁定测试用的证书被 `.gitignore`（`*.pem`、`*.key`）排除，CI 中测试会失败 | 为该目录加放行规则与 gitleaks 白名单，并加说明文件（一次性证书，CA 私钥已删除） |
| MEDIUM（安全） | 能推送分支的人可以修改部署工作流、拿到 root 密钥 | 部署 Secrets 只放在 production 环境；不再用 `secrets: inherit`；文档要求环境限制分支并审批 |
| MEDIUM（安全） | 用户上传的 HTML 或 SVG 在管理后台同源下打开，可以形成存储型 XSS | 对象响应一律作为下载，并加 CSP `sandbox` |
| MEDIUM（安全） | 服务器上的 OSS 密钥可以删除异地备份；接口容器也能读到它 | AccessKey 只能写入，生命周期规则删除旧备份，开启版本控制；密钥放到只有 backup 服务能读的 `backup.env` |
| MEDIUM（通用、安全） | `tar \| age` 在 sh 中不检查 tar 的退出码，截断的备份也会被标记为成功，随后删除旧的好备份 | 先打包再加密，失败时删除临时文件 |
| MEDIUM（通用） | 每天检查、按整天数比较，实际间隔是 15 天 | 按秒比较，留 2 小时余量 |
| MEDIUM（通用） | 证书邮箱为空时 Caddy 无法启动；不带 www 的域名变量没有传给 Caddy | `init-env.sh` 补上空值；`deploy.sh` 检查必填项；变量传给 Caddy；域名必须以 www. 开头 |
| MEDIUM（通用） | 新服务器拉不到 postgres、redis、caddy、rustfs 镜像 | CI 检查服务器缺少的第三方镜像并一并上传 |
| MEDIUM（通用） | 行数在导出之后另行统计，期间有写入时恢复校验会误报失败 | 行数从导出文件中统计 |
| MEDIUM（安全） | 部署前备份失败时留下不完整的文件，占用保留名额 | 失败时删除并停止部署 |
| MEDIUM（Flutter） | 两处默认使用 `TlsPolicy.current`，绕过 provider | 改为必须传入，只在 provider 中读取 |
| LOW（一并处理） | 首次部署时回滚目标不存在；回滚不恢复配置；旧镜像不清理；找不到的静态资源被长期缓存；`.env` 被替换后 backup 容器看到旧文件；恢复演练等待数据库的方式不可靠；`init-env.sh` 的权限窗口；`Uri.parse` 可能抛错；WebSocket 测试未关闭连接；Android 配置的注释过时；预读之后被抢先插入的分支缺少测试 | 全部修复 |
| LOW（未处理） | 备份没有签名；部署前的数据库备份未加密；SSH 断开时部署脚本被中断；Redis 密码出现在容器的命令行中 | 前两项写入《备份与恢复》的已知限制；后两项影响很小，暂不处理 |
