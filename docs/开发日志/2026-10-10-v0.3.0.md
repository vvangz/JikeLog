### 设计（ADR）

- [ADR-005 同步协议](../架构/ADR/ADR-005-同步协议.md)：通用记录表 + 字段级 HLC 时钟 + 文本补丁合并。

### 服务端（`server`）

- **数据模型**（迁移 `00002_sync.sql`）：
  - `records`：所有同步实体的通用表，字段与字段时钟为 JSONB
  - `sync_cursors`：每个账号的同步序号
  - `record_revisions`：修订历史
  - `user_keys`：被主密钥包裹的数据密钥
  - `attachments`：附件对象登记
  - `devices.last_ack_seq`：每台设备已确认的同步序号
- **同步引擎**（`internal/syncer`）：
  - 实体 schema 登记字段类型、长度、是否敏感、是否可合并、是否只能由服务端写入。
  - 推送逐字段处理：快进、文本补丁合并、最后修改覆盖；删除胜过编辑。落败一方的完整快照写入修订历史。
  - 记录"已吸收的客户端时钟"，推送重试是幂等的。
  - 单条变更校验失败只拒绝这一条；一批最多 100 条，请求体上限 4MB。
  - 拉取分页（最多 500 条，并限制总字节数），墓碑不下发字段。
- **文本补丁**（`internal/textpatch`）：带上下文的补丁，按 Unicode 码点定位，用 `strings.Index` 线性查找，防止构造输入消耗 CPU。
- **传输加密**（`internal/e2e`）：
  - 客户端上传临时 X25519 公钥，会话存 Redis 24 小时，并绑定账号和设备。
  - AAD 绑定实体、记录、字段和用途（值或补丁）。
  - 服务端支持新旧两把静态私钥并存，握手限流 60 次/小时/设备。
- **落库加密**（`internal/vault`）：
  - 每个账号一把数据密钥（DEK），由主密钥包裹；开发环境用本地主密钥，阿里云 KMS 在 v0.9.0 接入。
  - 解开的 DEK 在进程内缓存 10 分钟。
  - 字段密文的 AAD 绑定账号、记录和字段。
- **附件**（`internal/attachment`、`platform/storage`）：
  - 预签名 PUT，`Content-Length` 与 `Content-Type` 纳入签名。
  - 上传完成后服务端核对大小，生成 attachment 同步记录。
  - 单个附件上限 100MB，每个账号总量 2GB，未完成的上传也计入配额。
  - 每个账号最多 20 个未完成的上传，超过 1 小时未完成的由清理任务删除。
  - 删除后由后台任务清理对象；注销账号时按前缀删除该账号的全部对象。
- **实时通知**（`internal/realtime`）：
  - WebSocket 连接；写入提交后经 Redis `PSUBSCRIBE` 分发到各实例。
  - 每个连接只保留最新序号，连续的通知合并为一条；每个账号在单个实例上最多 10 个连接。
  - 每分钟重新校验设备会话，设备被下线后以 4401 关闭连接。
- **配置**：新增传输私钥、KMS、对象存储、附件限制等配置项。staging 和 production 拒绝使用示例密钥，生产环境的对象存储公开地址必须是 https。

### 移动端（`apps/mobile`）

- **本地数据库**：Drift。`records` 表与服务端结构对应，另含基准字段和基准时钟、待推送标记、冲突标记；同步元数据表；附件本地文件表。
- **HLC**：格式与服务端一致；收到远端时钟后推进本地时钟，但不跟随超前 4 分钟以上的时钟；持久化后重启仍保持单调。
- **同步引擎**：
  - 先推送后拉取；并发触发合并为一次运行，运行期间有新触发时在结束后补跑一轮。
  - 本地修改后防抖 2 秒再推送。
  - 推送期间继续编辑的字段保持待推送状态。
  - 合并结果不会被本地旧值再覆盖回去。
  - 被服务端拒绝的变更不再自动重试，再次修改后才重试。
- **传输加密与文本补丁**：Dart 端各自实现一遍，与 Go 端共用 `testdata/` 下的测试向量。
- **实时通知**：
  - 忽略本设备产生的通知。
  - 断线后按 1、2、4…60 秒退避重连。
  - 握手失败时先刷新令牌再重试。
  - 收到 4401 后停止重连。
- **同步生命周期**：
  - 登录后立即同步，并保持实时连接；回到前台时再同步一次；前台每 5 分钟检查一次。
  - 主动退出、注销账号或换成其他账号登录时，清空本机数据和附件文件。退出前先推送，仍有未同步的修改时提示用户。
  - 登录失效（令牌过期、设备被下线、在其他设备改了密码）时保留本机数据，同一账号重新登录后继续推送。
- **工作日志界面**：
  - 列表：按月分组，显示同步状态标记，下拉同步。
  - 编辑页：
    - 日期选择、地点联想
    - Markdown 工具栏与预览
    - 停止输入 1 秒后自动保存；离开页面时立即保存
    - 其他设备的修改实时刷新到编辑框（本地有未保存输入时保留本地输入）
    - 冲突提示横幅
  - 修订历史：查看并恢复任意版本。
- **附件界面**：
  - 选择文件后复制到应用目录，所属日志同步后再上传。
  - 下载后按 SHA-256 校验，用系统应用打开。
  - 上传失败显示原因，可以重试。
  - 删除日志时附件一并删除。
- **侧栏**：底部显示同步状态（同步中、离线、N 条待同步、最后同步时间），点击可以立即同步。
- **正式构建**：必须通过 `--dart-define` 指定生产环境的传输公钥，否则启动即报错。

## 关键决策

| 决策 | 原因 |
|---|---|
| 通用记录表 + schema 登记，不为每个模块单独建表 | 后续三个模块直接复用推送、合并、拉取和修订历史（ADR-005） |
| 字段级 HLC，加上客户端提交的 `baseClocks` | 判断"服务端是否在此期间修改过这个字段"，只在真正并发修改时才合并或覆盖 |
| 自定义上下文补丁，不用 diff-match-patch 的补丁文本格式 | Go 与 Dart 两端计位置的单位不同（字节、码点、UTF-16），中文长文本合并会失败 |
| 服务端记住已吸收的客户端时钟 | 合并后服务端时钟可能大于客户端时钟，重试时如果不识别，补丁会被重复应用 |
| 服务端能看到明文（不做端到端加密） | 服务端需要合并补丁，以后还要导出和发送提醒；用户换机不需要迁移密钥（ADR-006） |
| WebSocket 只通知，不传数据 | 丢一条通知不会丢数据，客户端在其他时机也会拉取 |
| 主动退出、换账号时清空本机数据；登录失效时保留 | 防止下一个账号看到上一个账号的内容，同时不因令牌过期丢失离线期间的修改 |
| 合并结果使用新的服务端时钟 | 沿用客户端时钟会让同一时钟对应两份文本，客户端在推送的值上继续编辑时会被当成快进，抹掉合并进来的修改 |
| 文件名加密，对象键不含文件名 | 对象存储的访问日志和运维人员都看不到文件名 |

## 问题与解决

1. **CI 中 `-race` 检出数据竞争**：生成的处理器把 `*gin.Context` 当作 context 传入。对象存储的 HTTP 请求从它派生出后台协程，而 gin 在处理器返回后会复用这个 Context。M2 的处理器改用请求本身的 context（`httpx.RequestContext`）。
2. **gitleaks 扫描整个提交历史**：早期提交在测试代码中直接写了测试向量私钥。之后改为从 `testdata` 读取，并在 `.gitleaks.toml` 中精确放行公开的测试和示例密钥。
3. **Windows 上 testcontainers 映射的端口落在系统保留范围**：连接被拒绝（"forbidden by its access permissions"）。启动对象存储容器失败时换端口重试。
4. **Drift 流查询在组件树销毁后残留 0 毫秒定时器**：测试框架报"Timer is still pending"。组件测试的数据库改用 `closeStreamsSynchronously: true`。
5. **组件测试中 `tester.runAsync` 与页面上的同步任务互相等待**：页面在虚拟时间中启动的同步任务，在真实时间里永远不会完成。改为在虚拟时间中发起操作，再推进时间直到完成。
6. **本机删除日志后页面重复返回**：监听器把本机删除误当成"其他设备删除"，也执行了一次返回。加标记区分。
7. **推送结果为"已合并"时被本地旧值覆盖**：应用服务端记录时传入本次推送的字段时钟，推送后没有再改过的字段以服务端结果为准。由收敛测试覆盖。
8. **file_picker 13 接口改为静态方法，`PlatformFile` 变为 base class**：适配新接口，并把文件选择器做成可注入的 Provider。
9. **Windows 上 `flutter test` 并行启动偶发"Connection closed before test suite loaded"**：本地改为单并发运行；覆盖率脚本支持传入额外参数。

10. **审查发现的合并缺陷**：拉取时把本地已修改字段的基准换成服务端新值，下次推送的补丁会把对方的修改当成本地删除，快进时直接抹掉。改为保留原基准，由服务端合并。修这个问题时又发现，合并结果沿用了客户端时钟（见关键决策），一并修正。两处都由新的收敛测试覆盖。
11. **编译时内存不足**：本机可提交内存只剩约 250MB（Docker/WSL 虚拟机占用），连 `go build -p 1` 都无法运行。重启 Docker Desktop 后恢复。

## 审查记录

三个审查（Go、Flutter、安全）的结论：没有安全方面的 CRITICAL；移动端 2 个 CRITICAL、两端合计 6 个 HIGH。CRITICAL、HIGH、MEDIUM 已全部修复并补了测试，部分 LOW 一并处理。

| 级别 | 问题 | 处理 |
|---|---|---|
| CRITICAL | 登录失效时清空本机数据，离线期间未同步的修改全部丢失 | 只在主动退出、注销、换账号时清空 |
| CRITICAL | 拉取时本地已修改字段的基准被换成服务端新值，推送时抹掉对方的修改；编辑框有未保存输入时同样会覆盖 | 保留原基准由服务端合并；编辑框三方合并；合并结果使用新的服务端时钟 |
| HIGH | 构造的文本补丁可长时间占用 CPU 和账号锁 | 只在提示位置前后 1 万字内查找，限制候选数，每次推送共享计算量预算；推送每账号每分钟 120 次 |
| HIGH | 首次创建数据密钥的事务回滚后，缓存中留下从未保存的密钥，之后的数据无法解密 | 新建的密钥在事务提交前不缓存 |
| HIGH | 合并通知时来源设备标记被保留，其他设备的修改被当成自己的而忽略 | 合并了不同来源时清除来源 |
| HIGH | 推送期间删除的记录不再推送；未推送的删除被拉取复活；其他设备删除后编辑页关闭时把记录写回 | 分别修复，已删除记录忽略后续写入 |
| HIGH | 一条无法解析的记录让同步永远失败（服务端与客户端都有） | 服务端只拒绝该条、拉取时跳过；客户端先换新会话重试，仍失败则跳过 |
| HIGH | 附件后台上传的异常未捕获，服务端 5xx 被当成永久失败 | 按错误类型区分"稍后重试"和"标记失败" |
| MEDIUM | 重试识别、快进时钟倒退、未知字段时钟、配额并发、未完成上传无上限、跨账号行锁、WebSocket 漏通知与 Redis 重连、发布无超时、握手无限流、旧私钥可用示例密钥、拉取一次读入过多、退出时附件文件残留与同步未停止、实时连接泄漏、附件 Content-Length 与下载半成品、修订恢复失败卡住等 | 全部修复 |

暂不处理的 LOW，记录在遗留事项中。

## 遗留事项与下一步

- 审查中暂不处理的 LOW，v0.9.0（安全加固）统一处理：
  - 传输加密的 AAD 不区分方向、不绑定会话（重放需先突破 TLS）。
  - 退出登录时不主动删除 Redis 中的传输加密会话（会话绑定设备，设备失效后无法使用）。
  - 服务端不校验附件的 SHA-256，完成上传后 15 分钟内预签名链接仍可覆盖对象（客户端下载时会校验）。
  - 注销账号时删除对象失败只记录日志，没有重试任务。
  - 附件清理任务没有行锁，多实例部署前需要加 `SKIP LOCKED`。
  - 每个账号的 WebSocket 连接上限按实例计算。
- 墓碑和修订历史目前一直保留（每条记录最多 50 份修订）；v0.9.0 加 30 天清理任务。
- 证书锁定、阿里云 KMS 与 OSS SSE-KMS 在 v0.9.0 接入。
- 关联笔记在 M3 实现（需要先有笔记模块）。
- **下一步 v0.4.0（M3 笔记）**：Markdown 与富文本双格式编辑器（先做编辑器技术验证）、文件夹、标签、收藏、四类附件、关联工作日志。
