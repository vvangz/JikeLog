# 2026-10-10 · v0.4.0 · M3 笔记

## 目标

笔记模块（需求 5）：

1. 支持 Markdown、富文本、代码块、表格和待办清单
2. 支持文件夹、标签、收藏
3. 支持图片、PDF、音频、文件等附件
4. 笔记可以关联到工作日志
5. 多设备同步与冲突版本查看（沿用 M2 的同步引擎）

## 完成项

### 编辑器技术验证

实施计划约定：M3 开始前先验证 appflowy_editor，不满足要求就换成 WebView 加载 Tiptap。验证结果（Flutter 3.47.6）：

| 项目 | appflowy_editor 6.2.0 | Tiptap 3.31 |
|---|---|---|
| 编译 | pub 上的版本无法编译（Flutter 新增了 `TextInputClient.onFocusReceived`），上游 main 已修复但未发布 | 与 Flutter 版本无关 |
| 代码块 | 核心包没有 | 支持，保留语言 |
| Markdown 往返 | 丢代码块、块之间不空行、有序列表全变成 `1.`、多次往返不稳定 | 全部保留；规范化一次后稳定 |

结论：采用 Tiptap。另外在 Chrome 中加载构建产物做了实测：CSP 哈希正确（脚本能运行）、注入的 `<script>` 与 `onerror` 不执行、附件图片正常显示、深浅主题正确。

### 设计

[ADR-007 笔记编辑器与数据模型](../架构/ADR/ADR-007-笔记编辑器与数据模型.md)：

- 两种编辑方式的正文都存成 GFM Markdown，`format` 只决定默认用哪种方式打开，可以随时切换
- 富文本编辑器是独立的前端工程，构建为单个 HTML 随 App 打包，离线可用
- 标签与关联的工作日志存成笔记上的多行文本，并发修改按补丁合并
- 敏感字段（标题、正文、标签、文件夹名）沿用工作日志的传输加密与落库加密

### 服务端（`server`）

- 新增同步实体 `note`、`note_folder`，在 schema 中登记即接入推送、合并、拉取与修订历史。
- 新字段类型 `KindFlag`（只能是 0 或 1）；字符串字段可限定取值（`Choices`）。
- 实体新增 `Attachable` 标记：只有工作日志和笔记可以添加附件。
- 没有数据库迁移（通用记录表无需改动）。

### 富文本编辑器（`apps/note-editor`，新工程）

- Tiptap 3 + Markdown 扩展：标题、加粗、斜体、删除线、行内代码、链接、引用、列表、待办、代码块、表格、图片、分隔线。
- **消息协议**：与 Flutter 只交换经过校验的 JSON 消息，类型、命令、主题颜色、链接、图片地址都有白名单或格式校验。
- **修改序号**：编辑器给每次发出的修改编号，Flutter 替换内容时带上已收到的编号。编辑器中有 Flutter 尚未收到的输入时拒绝替换，先送达输入，由 Flutter 合并后重试，正在输入的文字不会被其他设备的修改抹掉。
- **安全**：CSP 为 `default-src 'none'`，脚本只允许构建时计算出哈希的那一段，图片只允许 `data:`，没有任何网络通道。
- **图片**：正文中写作 `attachment:<附件 ID>`，编辑器向 Flutter 请求图片，Flutter 读本机缓存（必要时下载），缩小后以 `data:` 地址返回。网络图片不加载。
- 构建产物 `apps/mobile/assets/editor/index.html`（约 505KB）提交到仓库，CI 重新构建并检查一致。

### 移动端（`apps/mobile`）

- **本地库 v2**：
  - 新增派生索引表 `record_refs`（记录 → 标签、关联的工作日志、所属文件夹），随每次写入更新，用于筛选和反查。
  - 用真实的 v1 数据库文件测试升级。
- **同步引擎**：推送按估算的请求体大小分批（服务端上限 4MB）。此前一批固定 100 条，多篇长正文同时待推送时会被 413 拒绝并一直卡住。
- **笔记列表**：
  - 置顶在前，再按最后修改时间排序（取各字段 HLC 的最大值，拉取到的旧笔记不会排到最前面）。
  - 筛选：全部、收藏、未分类、文件夹（含子文件夹）、标签，并显示数量。宽屏时筛选面板常驻左侧。
  - 在当前文件夹或标签下新建的笔记自动归入该文件夹或带上该标签。
- **编辑页**：
  - 标题与正文停止输入 1 秒后自动保存；离开页面、切换编辑方式、进入后台时立即保存。
  - 富文本模式：WebView + 底部工具栏。按钮随光标处的格式高亮，在表格中显示表格操作。
  - Markdown 模式：沿用工作日志的编辑器，预览中显示附件图片。
  - 其他设备的修改实时合并到编辑器中（两种模式共用 `BodySync`）。
  - 冲突提示与修订历史。
  - 新建后什么都没写就返回，自动删除这篇空笔记。
- **信息面板**：文件夹、标签（带用过的标签建议）、关联的工作日志、附件。
- **文件夹与标签管理**：新建、嵌套、重命名、移动、删除（内容移到上一级）。标签可以重命名（同名合并）和删除。
- **关联工作日志**：工作日志编辑页新增"关联的笔记"，可以新建笔记、关联已有笔记、取消关联。
- **附件**：
  - 图片可插入正文，并可全屏缩放查看。
  - PDF 在 App 内阅读（pdfx）。
  - 录音与播放（record、just_audio，AAC）。
  - 其他文件交给系统应用打开。
  - 附件逐个添加，失败时提示原因。
- **修订历史**改为与实体无关，笔记可以查看并恢复冲突版本。
- 平台插件（WebView、录音、播放、PDF、打开链接、选择图片）都抽成可替换的 provider，组件测试使用假实现；测试用的假编辑器按真实协议应答。

## 关键决策

| 决策 | 原因 |
|---|---|
| 富文本用 WebView 中的 Tiptap，不用 appflowy_editor | 后者在 pub 上的版本无法编译、没有代码块、Markdown 往返丢内容（见技术验证） |
| 两种编辑方式都存 Markdown | 补丁合并对 JSON 不安全；两种方式切换无损；搜索和导出直接用 Markdown。代价是富文本不支持颜色、下划线、对齐 |
| 标签与关联存为笔记上的多行文本，不用独立实体 | 两台设备同时加标签时按补丁合并，都保留；独立实体在离线时会产生同名重复标签 |
| 编辑器构建产物提交到仓库 | Flutter 构建不依赖 Node；CI 检查产物与源码一致 |
| 富文本替换用"修改序号 + 确认/拒绝" | 编辑器的输入有 250 毫秒防抖，直接替换会抹掉这段时间的输入 |
| 笔记标题、正文、标签、文件夹名也加密 | 需求只要求工作日志加密，但笔记同样是个人内容，复用现有机制成本很低 |
| 未加密的元数据（文件夹结构、收藏、关联）对服务端可见 | 导出等服务端功能需要；ADR-007 中明确记录 |

## 问题与解决

1. **appflowy_editor 无法编译**：见技术验证，改用 Tiptap。
2. **Tiptap 把只有图片或空表格的文档当成空文档**：`isEmpty` 只看文字，按它保存会丢掉图片。改为只有"一个空段落"才算空。
3. **构建产物在 Windows 与 Linux 上是否一致**：源码在 Windows 工作区是 CRLF。转成 LF 后重新构建，产物的哈希完全相同。
4. **testcontainers 连接 `[::1]` 被 Windows 拒绝**：对象存储容器启动后的就绪检查拨号 IPv6 回环地址失败（PostgreSQL 容器不受影响）。改为手动启动只监听 IPv4 的 RustFS，用 `JIKELOG_TEST_S3_ENDPOINT` 指过去，已写入本地开发文档。
5. **Riverpod 3 暂停未被监听的 provider**：在工作日志页读取笔记列表时拿到空值，关联笔记的选择列表是空的。改为直接查本机库。
6. **组件测试中横向滚动的工具栏点不中**：滚动后需要先绘制一帧；底部的提示浮层也会挡住工具栏。测试中先等待。
7. **录音计时用 Stopwatch 时测试无法推进**：改为每秒累加计时器的次数，行为一样且可测试。
8. **代码规范插件禁止创建 `eslint.config.js`**：编辑器工程只用 TypeScript 严格模式检查（`noUnusedLocals` 等）。

## 审查记录

三个审查（通用、Flutter、安全）的结论：

- 安全审查没有 CRITICAL 和 HIGH
- 通用审查 1 个 HIGH，Flutter 审查 3 个 HIGH，其中两个是同一个问题

CRITICAL、HIGH、MEDIUM 已全部修复并补了测试，部分 LOW 一并处理。

| 级别 | 问题 | 处理 |
|---|---|---|
| HIGH | 编辑器页面就绪前到达的替换被丢弃，自动保存永远等待确认；页面重新加载时用打开时的旧内容初始化 | 就绪前只更新初始化内容并立即确认；初始化内容随修改更新；重新加载时视为已确认 |
| HIGH | 离开页面时取回编辑器内容没有超时，WebView 卡死时无法退出；保存失败也无法退出 | 取回内容 2 秒超时；保存失败提示后仍然退出 |
| HIGH | 笔记列表一次构建全部条目，每次刷新都对整篇正文做正则处理 | 按需构建；摘要只处理正文前 2000 字；内容未变时不通知 |
| MEDIUM | 切换编辑方式、离开页面时，未确认的替换没有清理，之后的修改不再合并 | 拆除编辑器前等待确认，仍未确认时把输入合并到替换内容上 |
| MEDIUM | 文件夹树容错过度：远处祖先被删除时整条链被拍平，并可能写出真正的循环 | 只在直接上级不存在或自身在环上时视为顶层；按原始上级链判断能否移动 |
| MEDIUM | 录音：重复点击、开始或停止期间关闭面板会泄漏计时器、留下明文录音文件；保存失败时临时文件残留 | 防重入、各个 await 之后检查页面状态、失败时删除；打开录音面板时清理上次残留 |
| MEDIUM | 附件添加失败没有提示，并会中断其余文件 | 逐个添加，失败时列出原因 |
| MEDIUM | 编辑页多处 await 之后未检查页面状态；删除失败后已停止保存 | 补充检查；删除成功后才停止保存 |
| MEDIUM | 进入后台时不保存，被系统结束进程会丢最后几秒的输入 | 进入后台时立即保存 |
| MEDIUM | 新建后不写就返回会留下空笔记并同步 | 离开时删除空笔记 |
| MEDIUM | 文件夹计数每次刷新约 O(文件夹² × 笔记) | 一次遍历后逐级累加 |
| MEDIUM | 宽屏判断用窗口宽度，没扣除常驻侧栏；筛选面板在底部面板中滚动冲突；大字号时标题栏溢出 | 按页面宽度判断；传入面板的滚动控制器；状态移到标题下方一行 |
| MEDIUM | 预览图片按原图解码 | 按显示宽度解码 |
| LOW（一并处理） | 导航白名单用 `endsWith`；正文、标签、关联超过服务端上限时笔记无法同步；把大文件当作图片整体读入；迟到的修改会重建已删除的记录；标签读改写不在事务中；保存失败后不再重试；标签建议读取全部正文；预览不随外部修改刷新；新建笔记不自动聚焦 | 全部修复 |

暂不处理的 LOW，记录在遗留事项中。
