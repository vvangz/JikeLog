# 2026-10-26 · v1.3.0 · 短信登录

## 目标

开通手机号验证码登录与找回密码。账号、App 与服务端的短信流程早已完成（v0.2.0），一直用 `JIKELOG_SMS_PROVIDER=disabled` 关着，缺的是真实的短信通道和发送前的人机验证。

与用户确认的做法：

- **没有企业主体**，微信登录暂不做（微信开放平台的开发者资质认证只对企业和组织开放）。
- 个人实名账号不能用阿里云普通"短信服务"：自定义签名无法通过实名制报备。改用**号码认证服务的"短信认证"**，使用系统赠送的签名（恒创联众）与模板，不需要审核。
- 人机验证用**阿里云验证码 2.0**（V3 架构，"一点即过"）。
- AccessKey 由用户直接写入服务器的 `.env`，不经过对话。RAM 用户只授予两项接口权限，并限制来源 IP 为服务器。

## 完成项

### 服务端

- `platform/aliyun`：阿里云 RPC 风格 OpenAPI 的最小客户端，手写 V3 签名（ACS3-HMAC-SHA256）。没有引入官方 SDK 及其大量依赖。签名用官方文档的固定参数示例做测试，结果逐字节一致。错误分为三类：网络层失败、阿里云服务端错误（5xx）、其他业务错误（附 Code、Message、RequestId，没有 Code 时附响应原文的前 256 字节）。
- `auth.AliyunSender`：调用 `SendSmsVerifyCode` 下发验证码。验证码仍由本服务生成、以 HMAC 存在 Redis 中并自行校验，阿里云只负责发送（模板参数 `{"code":…,"min":"5"}`）。四种用途对应四个赠送模板，可通过 `JIKELOG_SMS_TEMPLATE_*` 覆盖。错误映射：
  - `BUSINESS_LIMIT_CONTROL`、`FREQUENCY_FAIL` → 429"发送过于频繁"，保留冷却；
  - `MOBILE_NUMBER_ILLEGAL` 或非 +86 号码 → 字段错误"该手机号无法接收短信"；
  - 其余 → 记录日志并返回 503 `SMS_SEND_FAILED`；
  - 带 `isv.` 前缀的写法同样识别。
- `auth.AliyunCaptcha`：调用 `VerifyIntelligentCaptcha` 校验 App 提交的 `captchaVerifyParam`，场景 ID 由服务端指定。容灾策略：
  - 没有得到响应（网络错误、超时）或阿里云 5xx 时放行（阿里云的建议），但全服务每分钟最多放行 20 次；
  - 限流（429）、鉴权失败、响应无法解析、请求被取消时不放行。
- 每个 IP 每小时最多提交 60 次人机验证（新的限流桶 `captcha`），在调用阿里云之前检查。
- `SMSCodes.Send`：短信通道返回的业务错误直接交给客户端；只有通道频控时保留冷却期。
- 配置：
  - 新增 `JIKELOG_ALIYUN_ACCESS_KEY_ID/SECRET`、`JIKELOG_SMS_SIGN_NAME`、`JIKELOG_SMS_TEMPLATE_*`、`JIKELOG_CAPTCHA_SCENE_ID/PREFIX`；
  - 使用 `aliyun` 时校验必填项；
  - 去掉了"阿里云尚未接入"的启动报错。
- 系统信息新增 `features.captcha`（`region`、`prefix`、`sceneId`），不需要人机验证时省略。

### App

- `features/auth/captcha.dart`：
  - 底部弹层中的 WebView 加载内联页面，从阿里云 CDN 动态加载 `AliyunCaptcha.js`（官方要求，不能打包）；
  - 以 embed 模式显示验证，通过后经 `JikeCaptcha` 通道把结果交回；
  - 有加载中、加载失败与重试三种状态；
  - 页面参数经 JSON 编码，`<` 转义为 `\x3c`；
  - 只允许本页与验证组件的子框架加载。
- `sendWithCaptcha`：所有发送验证码的入口（验证码登录、找回密码、绑定 / 换绑手机号、用验证码改密码或注销）都先等系统信息查询完成，需要时完成人机验证再发送。用户关闭弹层时不发送、不进入倒计时。
- Windows 没有 WebView 实现：服务端要求人机验证时，`smsEnabled` 为 false，隐藏验证码登录与找回密码，帐号页的手机号不可操作，并提示"电脑端暂不支持短信验证，请在手机上操作"。改密码与注销照常用当前密码。

### 隐私政策

- 原政策承诺"启用短信服务前更新本政策并请你重新确认"。新增两处说明：
  - 发送验证码时，手机号与验证码交由阿里云号码认证服务发送；
  - 人机验证时，阿里云验证码组件采集设备与网络环境信息和操作行为。
- 官网 `docs/法律/隐私政策.md` 与 App 内 `policy_text.dart` 同步修改，`privacyPolicyVersion` 3 → 4，已同意的用户启动时会重新确认。
- 更新日期与生效日期均为 2026 年 10 月 26 日。

## 问题与解决

| 问题 | 原因 | 解决 |
|---|---|---|
| 个人账号用不了阿里云短信服务 | 签名实名制要求企业资质 | 改用号码认证服务的短信认证（赠送签名与模板） |
| 已登录后发送验证码也要人机验证 | `account.SendSMS` 一直会校验人机验证，App 之前从不提交 | 帐号相关的三个发送入口也走 `sendWithCaptcha`；Windows 上一并禁用 |
| 刚启动时点"获取验证码"可能跳过人机验证 | 系统信息尚未返回时 `captcha` 为空 | 发送前等待系统信息查询完成 |
| 放行策略过宽（审查发现） | 429 与无法解析的响应也会放行，攻击者可通过耗尽配额绕过验证 | 只在网络失败与 5xx 时放行，并加每分钟放行上限与按 IP 的校验次数限制 |

## 遗留事项

- RAM 策略中验证码 2.0 的权限名未经确认（官方只给出系统策略 `AliyunYundunAFSFullAccess`）。若校验返回 `Forbidden.*`，按报错中的权限名调整。
- 找回密码对未注册号码不调用阿里云，响应时间略短，理论上可用于推测号码是否注册（响应内容与频率限制一致）。
- 微信登录待有企业主体后再做。
