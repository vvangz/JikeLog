# ADR-007 笔记：编辑器、存储格式与数据模型

- 状态：已采纳
- 日期：2026-10-10

## 背景

需求第 5 条：笔记支持 Markdown、富文本、代码块、表格和待办清单；支持文件夹、标签、收藏；支持图片、PDF、音频、文件等附件；笔记可以关联到工作日志。

实施计划中，富文本编辑器首选 appflowy_editor，并约定 M3 开始前先做技术验证：如果它对表格和代码块的支持不满足要求，就换成 WebView 加载 Tiptap。

### 技术验证结果（2026-10-10，Flutter 3.47.6）

| 项目 | appflowy_editor | Tiptap 3.31（WebView） |
|---|---|---|
| 能否编译 | pub 上的最新版 6.2.0（2025-12）**无法编译**：Flutter 新增了 `TextInputClient.onFocusReceived`，编辑器没有实现。上游 main 分支已修复但未发布，只能依赖未发布的 git 提交 | 与 Flutter 版本无关 |
| 代码块 | 核心包**没有代码块**；插件包 appflowy_editor_plugins 最后发布于 2024-05 | 支持，保留语言标记 |
| 表格、待办清单 | 支持 | 支持 |
| Markdown 往返 | 丢失代码块；块之间不输出空行（分隔线与图片粘在一起）；有序列表全部变成 `1.`；多次往返结果不稳定 | 全部保留；第一次规范化之后多次往返结果完全一致 |
| `attachment:` 图片地址 | 保留 | 保留 |

结论：按计划的约定换用 Tiptap。

## 决策

### 1. 两种编辑方式，统一存成 Markdown

- **Markdown 模式**：沿用工作日志的编辑器（源码输入 + 工具栏 + 预览）。
- **富文本模式**：所见即所得，由 WebView 中的 Tiptap 3 实现。
- **两种模式的正文都存成 GFM Markdown**。`format` 字段只记录这篇笔记默认用哪种方式打开，两种方式可以随时切换。

富文本不存编辑器自己的文档 JSON，原因：

1. 同步引擎对长文本做补丁合并（ADR-005）。补丁合并 JSON 可能产生不合法的 JSON，Markdown 合并后总是可读的文本。
2. 两种模式互相切换不需要转换，不会丢内容。
3. 全局搜索（v0.7.0）和导出（v0.7.0）直接使用 Markdown，不必解析编辑器格式。

代价：富文本模式只提供 Markdown 能表达的格式，即标题、加粗、斜体、删除线、行内代码、链接、引用、有序/无序列表、待办清单、代码块、表格、图片和分隔线。文字颜色、下划线、对齐方式不提供。

打开笔记时，富文本编辑器会把正文规范化一次（例如表格列宽对齐）。规范化的结果只在用户真正编辑后才保存，单纯打开查看不会产生修改。

### 2. 富文本编辑器的打包与安全

- 编辑器是仓库中的独立前端工程 `apps/note-editor`（Vite + TypeScript + Tiptap）。它被构建成**单个 HTML 文件**，放在 `apps/mobile/assets/editor/`，随 App 一起打包，离线可用。
- 构建产物提交到仓库，CI 重新构建并检查与源码一致（与设计令牌的生成文件做法相同）。
- WebView 与 Flutter 之间只通过一个 JavaScript 通道交换 JSON 消息（设置内容、内容变化、执行格式命令、请求图片等）。
- 安全约束：
  - 页面的 CSP 为 `default-src 'none'`。脚本只允许构建时计算出哈希的那一段，图片只允许 `data:`。因此正文中夹带的 HTML 即使被解析，也无法执行脚本或访问网络。
  - WebView 拦截全部页面跳转；点击链接时交给系统浏览器打开，并先请用户确认。
  - 图片不让 WebView 直接读文件：编辑器遇到 `attachment:<id>` 时向 Flutter 请求，Flutter 读取本机缓存（必要时先下载），缩放后以 `data:` 地址返回。

### 3. 数据模型

两个新的同步实体，在服务端 schema 中登记即可接入同步（ADR-005）：

| 实体 | 字段 | 说明 |
|---|---|---|
| `note_folder` | `name`（敏感，≤50 字）、`parentId` | 文件夹，可以多层嵌套 |
| `note` | `title`（敏感，≤200 字）、`body`（敏感，长文本，≤10 万字）、`format`（`markdown` / `rich`）、`folderId`、`favorite`（0/1）、`pinned`（0/1）、`tags`（敏感，长文本）、`worklogs`（长文本） | 笔记 |

- **敏感字段**沿用工作日志的应用层传输加密和落库加密（ADR-006）。需求只要求工作日志加密，但笔记同样是个人内容，加密的成本很低，因此一并加密。
- **标签和关联的工作日志**存成笔记上的多行文本，每行一个标签名或一个工作日志 ID：
  - 两台设备同时给同一篇笔记加标签时，按长文本补丁合并，两边加的标签都保留。如果改成"标签实体 + 关联实体"，离线时两台设备新建同名标签，会产生两个重复的标签。
  - 客户端读取时去掉空行、重复行和不合法的行。
  - 本机另建一张派生索引表 `record_refs`（记录 ID、类型、值），用于按标签筛选、在工作日志中显示关联的笔记。
- **新增字段类型**：`KindFlag`（只能是 0 或 1）；字符串字段可限定取值（`Choices`），用于 `format`。

### 4. 文件夹的删除与移动

- 删除文件夹时，客户端先把其中的笔记和子文件夹移到上一级，再删除文件夹本身。
- 服务端不检查文件夹引用，客户端做容错处理：
  - 笔记指向的文件夹不存在或已删除（例如另一台设备同时删除了文件夹），这篇笔记显示在"未分类"中。
  - 两台设备同时移动文件夹形成循环（A 移进 B，B 移进 A），环上的文件夹按顶层文件夹显示。

### 5. 附件

沿用 M2 的附件实体，所属类型为 `note`。

- **图片**：插入到正文中，写作 `![文件名](attachment:<附件 ID>)`。两种模式中都直接显示图片，图片同时出现在附件列表中。
- **PDF**：App 内阅读（pdfx）。
- **音频**：App 内录音（record，AAC 格式）和播放（just_audio）。
- **其他文件**：用系统中的应用打开。

### 6. 冲突版本查看

沿用 M2 的修订历史，改成与实体无关：笔记的修订详情显示标题和渲染后的正文，可以恢复。

## 备选方案

- **appflowy_editor**：见验证结果。如果使用它，需要依赖未发布的 git 提交，自己补齐代码块和 Markdown 编解码，并且每次升级 Flutter 都可能再次无法编译。
- **flutter_quill**：维护活跃，但移动端不支持表格（上游 issue #2651）。
- **富文本存编辑器的文档 JSON，按块 ID 合并**：需要再实现一套 JSON 合并，而且两种格式互相转换会丢失内容。
- **标签和关联各用独立实体**：离线时会产生同名的重复标签，需要额外的去重和重新关联逻辑。

## 影响

- 仓库新增一个前端工程，CI 的"设计令牌与管理后台"任务会同时构建和测试编辑器。
- Flutter 的组件测试无法运行 WebView。编辑器本身用 vitest 测试（Markdown 往返、命令、消息协议），Flutter 一侧用假的 WebView 通道测试消息处理；富文本模式的实际效果在真机上验收。
- 正文是 Markdown，以后的 Windows 客户端可以继续用同一个编辑器（WebView2）。
