# ADR-009 记账：数据模型、金额与统计

- 状态：已采纳
- 日期：2026-10-11

## 背景

需求第 7 条：记账要记录收入、支出、转账和借贷，每条记录包含金额、日期、分类和备注，并提供分类占比与账户余额的统计。

实施计划 3.6 节定下了以下方向：
- 账户：现金、储蓄卡、信用卡、支付宝、微信等，可设初始余额。
- 分类：收入和支出各有两级，并预置默认分类。
- 借贷：记录对方和到期日。
- 金额以"分"为单位，存为整数。
- 统计全部在本地离线计算。

## 决策

### 1. 四个同步实体

| 实体 | 字段 | 加密 |
|---|---|---|
| `ledger_account` 账户 | `name`、`type`（cash/debit/credit/alipay/wechat/other）、`initialBalance`、`archived`、`sortOrder` | 名称、初始余额 |
| `ledger_category` 分类 | `name`、`kind`（expense/income）、`parentId`（两级）、`icon`、`archived`、`sortOrder` | 名称 |
| `ledger_loan` 借贷 | `direction`（lend 借出 / borrow 借入）、`counterparty` 对方、`dueDate` 到期日、`note`、`settled` 已结清 | 对方、备注 |
| `ledger_entry` 流水 | `type`、`amount`、`fee` 手续费、`date`、`accountId`、`toAccountId`、`categoryId`、`loanId`、`note` | 金额、手续费、备注 |

### 2. 金额：以"分"为单位的整数字符串，并且加密

- 新增字段类型 `KindMoney`：十进制整数字符串，单位为分，只接受规范写法。
  - 没有前导零，不允许"-0"，绝对值小于 10^15。
  - 流水金额必须大于 0，手续费不能为负。账户的初始余额可以为负，表示信用卡欠款。
- 用字符串而不用整数，是因为同步协议只支持对字符串字段做应用层加密（ADR-006）。金额属于个人财务信息，和名称、备注一起加密。服务端不需要金额做任何计算，加密后它也看不到。
- App 中全部用整数（分）计算，只在显示时格式化为元，避免浮点误差。

### 3. 流水类型与余额

| 类型 | 账户余额 | 待收 / 待还 |
|---|---|---|
| income 收入 | 账户 + 金额 | — |
| expense 支出 | 账户 − 金额 | — |
| transfer 转账 | 转出账户 − 金额 − 手续费；转入账户 + 金额 | — |
| lend 借出 | 账户 − 金额 | 该笔借贷待收 + 金额 |
| borrow 借入 | 账户 + 金额 | 该笔借贷待还 + 金额 |
| collect 收款 | 账户 + 金额 | 待收 − 金额 |
| repay 还款 | 账户 − 金额 | 待还 − 金额 |

- 账户余额 = 初始余额 + 以上变动之和。
- 净资产 = 各账户余额之和 + 待收 − 待还。
- 转账的手续费计入支出统计，归入"手续费"分类，不影响转入账户。
- 收入、支出必须有分类；借贷类流水关联一笔借贷（`loanId`），没有分类。
- 借贷的待收或待还 = 借出（借入）的金额之和 − 收款（还款）的金额之和。为 0 时可以标记"已结清"。
- 字段之间的约束（例如转账必须有转入账户）由 App 保证。服务端只按实体做通用校验；App 读到不完整的流水时，不计入统计。

### 4. 预置分类：按账号生成固定 ID

- 账号第一次使用记账时，App 写入预置分类，例如餐饮、交通、购物、工资。
- 这些分类的 ID 由账号 ID 和分类代号确定地生成（UUIDv5），两台设备各自初始化时写的是同一批记录，同步后自然合并，不会出现两份。
- 用户可以重命名、隐藏预置分类，也可以新增自己的分类。

### 5. 删除与隐藏

- 已有流水引用的账户和分类不能删除，只能**隐藏**（`archived`）。隐藏后不再出现在选择列表中，历史流水和统计照常显示它的名称。
- 没有流水引用时可以删除。
- 删除借贷时，一并删除它的借贷类流水，删除前提示。

### 6. 统计在本地计算

- 统计内容包括：
  - 按月或按年的收支合计。
  - 分类占比（饼图）和分类排行。按一级分类汇总，点击后看二级。
  - 收支趋势：月视图按日，年视图按月。
  - 各账户余额、净资产，以及待收和待还。
- 统计全部由本地数据实时计算，不存储、不上传。1 万条流水时，单次计算在毫秒级。
- 图表使用 fl_chart。

## 后果

- **好处**：
  - 金额、名称、对方、备注在服务端都是密文，管理员和数据库都看不到个人财务数据。
  - 统计离线可用。
  - 预置分类多设备不重复。
- **代价**：
  - 服务端无法做任何金额相关的统计或导出。v0.7.0 的导出需要在 App 端解密后生成，或者由服务端在用户发起时临时解密生成。
  - 字段之间的约束只在 App 端保证。
