# ADR-006 工作日志加密：应用层传输加密 + 落库信封加密

- 状态：已采纳
- 日期：2026-10-09

## 背景

需求第 10 条要求"工作日志模块内容需要传输加密"。全站已经使用 TLS，但以下几种情况下 TLS 保护不到明文：

- 用户手机里装了抓包工具的 CA 证书（正式包只信任系统证书，但调试包和 root 设备不受此限）
- 公司网络的 TLS 解密代理
- 证书锁定要到 v0.9.0 确定生产域名后才能加上

另外，工作日志存进数据库后，DBA、备份文件、SQL 注入等渠道也不应直接看到明文。

## 决策

### 1. 哪些字段加密

schema 中标记为"敏感"的字段需要加密。M2 包括：

- 工作日志：`location`（工作地点）、`content`（工作内容）
- 附件：`fileName`（文件名）

`date` 等字段保持明文，因为服务端排序、导出和提醒调度要用到。

### 2. 传输：X25519 + HKDF + AES-256-GCM

1. 服务端持有一对静态 X25519 密钥：私钥在服务器环境变量中，公钥通过 `--dart-define` 编译进 App。
2. App 每次启动（或会话过期后）生成一对临时密钥，调用 `POST /api/v1/sync/e2e/session` 上传临时公钥。
3. 双方各自计算会话密钥：
   ```
   shared = X25519(己方私钥, 对方公钥)
   key    = HKDF-SHA256(shared, salt = 客户端公钥 ‖ 服务端公钥, info = "jikelog-e2e-v1")
   ```
   服务端把会话（客户端公钥、所属账号和设备）存入 Redis，有效期 24 小时，返回会话 ID。会话绑定到登录设备，被其他账号或设备拿去也用不了。
4. 推送和拉取时，敏感字段的值和补丁都用 AES-256-GCM 加密：
   - 格式为 `base64(12 字节随机 nonce ‖ 密文 ‖ 16 字节标签)`，会话 ID 放在请求头 `X-JikeLog-E2E`
   - 附加数据（AAD）为 `jikelog-e2e-v1|<entity>|<id>|<field>|<v 或 p>`（v 表示值，p 表示补丁），把密文绑定到具体的记录和字段，防止被挪到别的字段或记录上
5. 会话过期或服务端找不到会话时，返回 `409 E2E_SESSION_INVALID`，客户端重新握手后重试。

这样即使 TLS 被中间人解开，看到的也只是密文。中间人没有服务端私钥，也就无法冒充服务端：App 只信任内置的公钥。

### 3. 落库：每个用户一把数据密钥（DEK）

- 用户第一次写入敏感字段时，生成 32 字节随机 DEK，由 KMS 主密钥加密后存入 `user_keys` 表。
- 字段密文格式为 `v1:base64(nonce ‖ 密文 ‖ 标签)`，AAD 为 `jikelog-rest-v1|<user>|<record>|<field>`。
- 修订历史中的内容同样以密文保存。
- 解开的 DEK 在进程内缓存 10 分钟，避免每次请求都调用 KMS。
- KMS 用 `KeyWrapper` 接口隔离：
  - 开发和测试环境用本地主密钥 `JIKELOG_KMS_LOCAL_MASTER_KEY`（AES-256-GCM 包裹）
  - v0.9.0 接入阿里云 KMS。主密钥轮换时，只需重新包裹 DEK，不用重加密数据
- 注销账号时 DEK 随账号一起删除，备份里残留的密文因此也无法再解开。

### 4. 服务端处理流程

推送：传输解密 → 合并（在明文上做补丁应用和比较）→ 落库加密。
拉取：落库解密 → 传输加密。

明文只在单个请求的内存中短暂存在，不写日志。访问日志不记录请求体。

## 备选方案

- **端到端加密（服务端看不到明文）**：最安全，但服务端无法做补丁合并，后续的服务端导出和备忘录提醒也做不了；用户换手机还要迁移密钥，丢了就再也恢复不了数据。不符合需求中"版本合并""数据导出"的要求。
- **只依赖 TLS 和证书锁定**：不满足"再加一层传输加密"的要求，而且证书锁定要等到 v0.9.0。
- **服务端也用临时密钥（完整的前向保密）**：服务端需要用静态密钥给临时公钥签名，复杂度更高。现在的方案中，如果服务端静态私钥泄露，攻击者可以解开此前录下的流量，但前提是同时拿到了 TLS 流量。这一风险可以接受，靠定期轮换静态密钥来缓解。

## 影响

- 每次 App 启动多一次握手请求（约 1 个 RTT）。
- 服务端静态私钥和 KMS 主密钥是两份新的关键机密：
  - 开发示例值放在 `.env.example` 中
  - staging 和 production 环境禁止使用示例值，配置校验时会拒绝启动
- 轮换服务端静态密钥需要发布新版 App。服务端支持配置一把旧私钥（`JIKELOG_E2E_PREVIOUS_PRIVATE_KEY`），在新旧版本 App 共存期间两把都能用。
