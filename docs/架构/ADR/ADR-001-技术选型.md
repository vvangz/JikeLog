# ADR-001 技术选型

- 状态：已采纳
- 日期：2026-10-08

## 背景

需求要求本期先交付 Android 客户端、Web 管理后台和服务端，之后再做 Windows 客户端。服务要部署在云服务器上，要求"高效、低延迟"。技术栈由开发方自行选择（需求第 11 条）。云厂商已确定为阿里云，Web 端只做管理后台。

## 决策

| 层 | 选型 | 版本（2026-10） |
|---|---|---|
| 客户端 | Flutter + Riverpod + go_router + Drift(SQLite/FTS5) | Flutter 3.47.6 / Dart 3.13.5 |
| 服务端 | Go + Gin + oapi-codegen（strict server）+ pgx + sqlc + goose + asynq | Go 1.27.1 / Gin 1.12.0 / oapi-codegen 2.8.0 |
| 数据库 | PostgreSQL（生产用阿里云 RDS） | 17 |
| 缓存/队列 | Redis（生产用阿里云 Tair） | 7.4 |
| 对象存储 | 阿里云 OSS；本地开发用 S3 兼容的 RustFS | RustFS 1.0.1 |
| 推送 | 极光 JPush + 厂商通道，实现在 `Pusher` 接口后面 | — |
| 管理后台 | React + Ant Design + Vite + TanStack Query + openapi-fetch | React 19.3 / antd 6.6 / Vite 8.3 / TS 6.0 |
| 设计令牌 | Style Dictionary（负责解析引用）+ 自定义生成器（输出 Dart / CSS / TS） | 5.6.0 |
| 工程规范 | pnpm workspace、lefthook、commitlint、Release Please、GitHub Actions、gitleaks | — |

## 理由

- **Flutter**：一套代码先出 Android，之后加 Windows 不需要重写。主题系统和字体回退（Space Grotesk → MiSans）好实现。离线数据库（Drift）和富文本编辑器（appflowy_editor）的生态够用
- **Go**：内存占用小，冷启动快，适合承载大量 WebSocket 长连接；编译成单个二进制，部署简单
- **契约优先**：用 OpenAPI 生成 Go 的严格类型接口和 TS 类型，避免三端字段不一致
- **PostgreSQL**：事务、JSONB（字段级时钟）、行级锁（`SELECT … FOR UPDATE` 合并）都能满足同步引擎的需要

## 与原计划的差异

- 计划中写的是 React 18 / Ant Design 5 / PostgreSQL 16。立项时（2026-10）的稳定版已经是 React 19 / Ant Design 6，PostgreSQL 17 在阿里云 RDS 上也已成熟，因此改用较新的稳定版本
- TypeScript 用 6.0 而不是 7.0：typescript-eslint 8.71 目前只支持 TS < 6.1
- 计划中开发环境用 MinIO。但 MinIO 已停止在 Docker Hub 发布社区版镜像，因此改用同样兼容 S3 协议的 RustFS。生产环境不受影响，仍用阿里云 OSS

## 备选方案

- 原生 Kotlin + Jetpack Compose：Android 体验最好，但做 Windows 客户端时要另写一套，所以没有选
- Java/Spring Boot：生态成熟，但资源占用更高；本项目追求低延迟和低成本，所以没有选
- Vue 3 + Naive UI：同样可行。选 Ant Design 是因为它基于 token 的主题系统与设计令牌对接更直接
