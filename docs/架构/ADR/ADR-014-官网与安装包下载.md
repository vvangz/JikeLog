# ADR-014 官网与安装包下载：VitePress 静态站点、文档单一来源、安装包镜像到自有服务器

- 状态：已采纳
- 日期：2026-10-14

## 背景

v1.1.0 之后，Android 与 Windows 两个客户端都已发布，但用户只能从 GitHub Release 下载安装包，使用说明也只在仓库里。需要一个官网，包括：产品介绍、两个平台的下载、使用教程、更新日志、隐私政策与用户协议，以及备案后的 ICP 备案号。

约束：

- 国内访问 GitHub 经常很慢或打不开，下载地址需要在自己的服务器上。
- 使用说明（`docs/使用说明`）已经按章维护，并随功能更新。官网不应再复制一份。
- 官网与管理后台、接口同在 `www.pingvv.top` 下（ADR-012），同源：官网页面如果被注入脚本，就能以本域名身份调用接口。
- 服务器是 1.7G 内存的单机，不再增加常驻服务。

## 决策

### 1. VitePress 生成静态站点

`apps/site` 用 VitePress 生成静态 HTML，由现有的 Caddy 直接提供，不增加服务。

- **版本**：VitePress 2.0.0-alpha。1.6.4 依赖的 Vite 5 有高危公告（GHSA-fx2h-pf6j-xcff），CI 的 `pnpm audit` 不能通过；2.0 使用 Vite 8，与仓库其他前端一致。VitePress 自己的文档站也在用 2.0。升级到正式版时检查主题插槽与配置是否变化。
- **页面**：首页（自定义 Vue 组件）、下载、使用教程、更新日志、隐私政策、用户协议、404。生成 `sitemap.xml`，有 `robots.txt` 与 Open Graph 分享图。
- **外观**：独立的配色（青绿到天蓝），不沿用 App 的咖色主题；深浅两套主题，正文对比度满足 WCAG AA。首页的产品界面示意用 HTML/CSS 绘制，不使用截图。
- **字体**：只用系统字体。不加载外部字体（CSP 只允许本站资源，国内也访问不到 Google Fonts），也不分发 MiSans（许可不允许单独分发字体文件）。
- **搜索**：VitePress 本地搜索。中文没有空格，默认分词会把整句当作一个词，改用 `Intl.Segmenter` 按词切分。

### 2. 文档只有一份

构建前 `scripts/sync-docs.mjs` 把仓库中的 Markdown 同步为官网页面：

| 来源 | 官网 |
|---|---|
| `docs/使用说明/NN-章节.md` | `/guide/<英文网址>`（网址在 `lib/docs.mjs` 中登记，新章节未登记时构建失败） |
| `docs/使用说明/README.md` 的章节表 | 教程首页的章节卡片 |
| `docs/发布说明/vX.Y.Z.md` | `/changelog/vX.Y.Z`，并生成版本列表 |
| `docs/法律/隐私政策.md`、`用户协议.md` | `/privacy`、`/terms` |

同步时先检查文档：出现 `<script>`、事件属性（`onerror=`）、`javascript:` 链接、`<iframe>`、`<meta>`、`<form>` 等时构建失败（代码块与行内代码中的示例不算）。然后改写链接：章节之间的链接改为官网地址；GitHub 风格的锚点（`#5-修订历史`）改为 VitePress 的写法（`#_5-修订历史`）；指向官网自身的完整地址改为站内路径；官网上没有的仓库文件改为 GitHub 链接。代码块中的内容不动。

### 3. 安装包镜像到自有服务器

发布时，Release Please 等 APK 与 Windows 两个签名任务完成后再调用部署（任一失败也照常部署；工作流被取消时不部署）。两个签名任务输出签名后安装包的 SHA-256，作为部署工作流的输入。

部署工作流先在**不带 production 环境的任务**中构建官网、收集安装包（`scripts/collect-downloads.sh`），产物交给部署任务。官网的第三方依赖因此接触不到服务器的 SSH 密钥。收集安装包时：

1. 列出该版本 Release 的附件，只下载 `jikelog-<版本>.apk`、`.msix`、对应的 `.sha256` 与 `jikelog-windows.cer`。没有任何安装包时跳过；下载失败时报错。
2. 安装包与签名任务输出的校验值核对。`.sha256` 与安装包同在 Release 中，只靠它不能证明 Release 中的文件在签名后没有被替换。手动部署时没有这个输入，只给出警告。
3. 用 `apksigner` 核对 APK 的签名证书与仓库变量 `APK_CERT_SHA256` 一致，用 `openssl` 核对 Windows 证书的指纹与 `WINDOWS_CERT_THUMBPRINT` 一致。两个变量为空时直接失败（否则任何证书都能"通过"）。
4. 生成 `latest.json`（版本、Release 的发布时间、每个文件的名称、大小、SHA-256，证书另有 SHA-1 指纹）。缺少 `.sha256` 或证书的平台不收录并给出警告（Release 可能还没上传完），校验值不符时失败。
5. `deploy.sh` 先解到临时目录、删除其中的软链接（Caddy 会跟随软链接），再换上并原子地切换 `downloads/current`。重新部署同一版本时原内容先移开，失败时换回。Release 中没有安装包时不切换，下载页保持上一个版本。

官网上线之前的版本没有 `apps/site`，手动重新部署这些版本时只部署程序，官网与下载页保持现状。

官网下载页在浏览器中读取 `/download/latest.json`，校验每个字段（版本号格式、文件名只能是 `jikelog-*.apk|msix|cer`、SHA-256 格式），显示版本、大小与校验值。读不到或不合法时引导到 GitHub Release。每张下载卡片都附 GitHub 备用链接。

不用阿里云 OSS 公共读：要多一个存储桶和写入密钥，按流量计费；单个安装包约 30MB，用户量下 ECS 带宽够用。将来下载量大时可以把 `downloads/` 改为 OSS + CDN，官网只需改 `latest.json` 中的地址。

### 4. 安全

- **CSP**：每个页面在 `<meta>` 中带 CSP，只允许本站脚本，不使用 `'unsafe-inline'`。VitePress 生成的两段内联脚本（深浅主题判断、系统识别）按内容哈希放行，哈希固定在 `lib/csp.mjs` 中：页面里出现任何其他内联脚本时构建失败，而不是自动放行。升级 VitePress 后若这两段脚本变化，确认来源后更新哈希。`<meta>` 不支持的 `frame-ancestors` 由 Caddy 的响应头补上，全站另加 `X-Frame-Options: DENY`。
- **剩余风险**：附件的 `Content-Type` 由上传者声明，存储桶与官网同源，因此 `script-src 'self'` 在理论上也包括用户上传的、声明为 JavaScript 的附件。利用它需要先在官网页面中注入 HTML，而官网内容只来自仓库并经过上述检查。后续由服务端限制附件类型的白名单，或把对象存储移到独立的子域名。
- **下载**：`/download/` 下的文件带 `Content-Security-Policy: sandbox; default-src 'none'`，安装包一律 `Content-Disposition: attachment`，并设置正确的 `Content-Type`；不列目录。
- **页面不含用户数据**，没有表单和登录；`latest.json` 只由部署工作流生成。

### 5. 路由

Caddy 中官网是兜底的 `handle`：接口、对象存储、管理后台、下载各有自己的路径，其余都交给官网。地址不带 `.html`（`try_files {path} {path}.html {path}/index.html`）；Caddy 自己找不到文件时显示官网的 404 页。出错时站点级的响应头不再生效，而原路径设置的头会保留（例如 `/admin/assets/` 的一年缓存、安装包的类型），所以 404 处理中逐一改写这些头。根路径不再跳转到管理后台。`deploy/production/tests/caddy-smoke.sh` 用真实的 Caddy 检查这些路由与响应头，在 CI 中运行。

## 备选方案

| 方案 | 不采用的原因 |
|---|---|
| 手写静态 HTML | 教程有十章并持续更新，需要侧栏、站内搜索、上下章导航，手写难以维护 |
| Astro / Next.js | 功能更多，但这里只是文档加几个介绍页；VitePress 直接渲染 Markdown，配置最少 |
| 下载链接只指向 GitHub Release | 国内经常打不开 |
| 官网单独用一个子域名 | 要再申请证书、改 CSP 与 Caddy 配置；同源的风险已由严格 CSP 控制 |

## 影响

- 新增 `apps/site`（pnpm 工作区成员）与 `docs/法律/`。修改使用说明时，官网在下次发布时随之更新。
- 部署时多上传 `site.tar.gz` 与 `downloads.tar.gz`（约 70MB，主要是安装包），服务器上保留最近 3 个版本。
- 隐私政策与用户协议目前是草稿，运营者信息待填写；App 内的文本（`policy_text.dart`）须在审定后同步修改，并递增 `privacyPolicyVersion`。
- ICP 备案通过前，官网与接口一样无法从公网访问。
