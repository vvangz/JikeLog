# ADR-010 全局搜索与数据导出

- 状态：已采纳
- 日期：2026-10-11

## 背景

本期覆盖两条需求：
- **需求第 9 条**：全局搜索覆盖四个模块，也可以只搜某个模块，支持按时间和内容筛选。
- **需求第 8 条**：支持数据导出。

实施计划给出的方向：
- 3.7 节：客户端用 SQLite FTS5 trigram 建本地索引，少于 3 个字的查询退回 LIKE；1 万条数据时查询在 100ms 以内。
- 3.8 节：导出在服务端异步执行，按模块生成 xlsx、Markdown、ICS、CSV 和全量 JSON，打包成 zip 放到对象存储，通过预签名链接下载，完成后推送通知。

## 决策

### 1. 搜索：本地 FTS5 trigram 索引

- 本地库新增 FTS5 虚拟表 `search_index`，使用 trigram 分词，中文、英文都能按任意子串匹配，不区分大小写。
  - 每条记录在表中对应一行，包含：记录 ID、实体、日期（`YYYY-MM-DD`，用于时间筛选）、标题、正文。
  - 与 `record_refs` 一样是派生数据：`RecordStore` 每次保存记录时同步更新，覆盖本地写入和同步应用两种情况；删除后移除对应的行。
  - 本地库升级到 v4 时，由已有记录一次性重建索引。
- 各实体的索引内容如下：

| 实体 | 标题 | 正文 | 日期 |
|---|---|---|---|
| 工作日志 | 地点 | 内容（Markdown 转为纯文本） | 日志日期 |
| 笔记 | 标题 | 正文（Markdown 转为纯文本）与标签 | 最后修改日期 |
| 备忘录 | — | 内容 | 提醒时间所在日期 |
| 流水 | — | 备注 | 记账日期 |
| 账户、分类、借贷 | 名称 / 对方 | 借贷备注 | — |

- **流水还能通过分类、账户和借贷对方搜到**：
  - 账户、分类、借贷本身不作为搜索结果，只用于把流水"带出来"。
  - 关键词命中某个分类、账户或借贷时，引用它的流水也算命中。命中一级分类时，它下面二级分类的流水同样算命中。
  - 这样做不需要把分类名写进流水的索引，改分类名后不用重建流水的索引。
- **查询规则**：
  - 关键词按空格拆开，最多 5 个，多个关键词之间是"并且"的关系。
  - 每个关键词各自求出命中的记录（含上一条中被带出来的流水），再取交集。
  - 3 个字及以上的关键词用 FTS5 `MATCH` 查询；不足 3 个字的用 `LIKE` 扫描索引表。1 万条记录时两种方式都在毫秒级。
  - 可以按模块筛选（工作日志、笔记、备忘录、记账），也可以按日期区间筛选。
- **排序与展示**：
  - 结果按日期从新到旧排序，按模块分组，每组显示条数。最多返回 200 条。
  - 片段与高亮在 Dart 中计算：截取第一个命中位置附近的文字，标出所有关键词。不使用 FTS5 的 `snippet()`，因为 `LIKE` 查询无法使用它，两种方式也应显示得一样。

### 2. 导出：服务端异步生成 zip

- **任务**：
  - 新增 `exports` 表记录导出任务。用户在 App 中选择模块和是否包含附件后发起，同一账号同时只能有一个进行中的任务，每天最多发起 5 次。
  - 沿用 ADR-008 的做法，用 PostgreSQL 表领取任务（`FOR UPDATE SKIP LOCKED`），不引入 asynq。
  - 领取后独占 30 分钟。超时未完成时，由任一实例重新领取；最多尝试 3 次，仍失败则标记为失败。
- **生成**：
  - 服务端逐页读取该账号的记录，解开落库加密后生成文件，写入本地临时 zip，完成后上传到对象存储。
  - 对象键为 `u/<用户>/exports/<任务>.zip`，与附件共用账号前缀，注销账号时一并删除。
- **zip 的内容**：

| 路径 | 内容 |
|---|---|
| `README.txt` | 导出时间、包含的模块、各文件说明 |
| `data.json` | 所选模块的全部记录（解密后的字段），可用于备份或迁移 |
| `工作日志/工作日志.xlsx` | 每天一行：日期、地点、内容、附件数 |
| `工作日志/<日期>.md` | 每天一篇，附件链接指向 `附件/` |
| `笔记/<文件夹>/<标题>.md` | 按文件夹存放；`attachment:<ID>` 引用改写为指向 `附件/` 的相对路径 |
| `备忘录/备忘录.ics` | 可导入日历；带提醒的备忘录写入 `VALARM` |
| `备忘录/备忘录.csv` | 时间、全天、内容、提醒、是否完成 |
| `记账/记账.xlsx` | 流水、账户、分类、借贷四个工作表，金额单位为元 |
| `记账/流水.csv` 等 | 与 xlsx 中的工作表一一对应 |
| `附件/<附件 ID>/<文件名>` | 选择包含附件时才有，只包含所选模块的附件 |

  - CSV 带 UTF-8 BOM，Excel 可以直接打开。
  - 文件名中的非法字符替换为 `_`，同名文件追加序号。
- **下载**：
  - 完成后 App 通过接口获取预签名下载链接，有效期 10 分钟。
  - 导出文件是明文，**保留 24 小时**后自动删除；用户也可以提前删除。
- **通知**：完成或失败时，向发起导出的设备推送一条通知，内容只有"导出已完成"或"导出失败"，不含数据。
- **接口**：
  - `POST /api/v1/exports`：发起导出。
  - `GET /api/v1/exports`：最近的导出任务。
  - `GET /api/v1/exports/{id}/download`：获取下载链接。
  - `DELETE /api/v1/exports/{id}`：删除导出文件。

## 备选方案

- **搜索时在服务端检索**：敏感字段在服务端是密文，无法检索；而且离线时用不了。
- **搜索索引中把分类名写进流水**：搜索时少一步，但改分类名后要重建所有相关流水的索引；同步时分类和流水的到达顺序也不固定，处理起来更复杂。
- **在 App 中生成导出文件**：
  - 好处：导出文件不经过服务器。
  - 问题：
    - 本机未必有全部附件，需要先逐个下载。
    - 本机数据可能还没同步完整。
    - 在手机上生成大文件既耗电又占空间。
  - 计划中已确定在服务端导出，ADR-006 也为此保留了服务端解密的能力。
- **用 asynq 执行导出任务**：需要额外的 Redis 队列语义和监控。导出量很小，PostgreSQL 表足够，与备忘录提醒的做法一致。

## 影响

- 本地库升级到 v4，第一次启动新版本时要重建一次搜索索引，1 万条记录约需 1 秒。
- 每次保存记录时多写一行索引，对写入性能的影响可以忽略。
- 服务端新增依赖 excelize，用于生成 xlsx。
- 导出文件在对象存储中以明文保存，最多 24 小时；下载链接只有 10 分钟有效。
- 生成导出文件需要服务器的临时磁盘空间，最多约为该账号附件总量（默认上限 2GB）再加上文本数据。
