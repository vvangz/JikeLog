## 关键设计（详见各里程碑文档）

| 主题 | 方案 | 里程碑 |
|---|---|---|
| 认证 | 用户名+密码（argon2id）/ 手机号+短信（需开通短信，未开通时接口返回 SMS_DISABLED，App 隐藏相关入口）；JWT 15 分钟 + 轮换式 Refresh Token 30 天，按设备管理 | v0.2.0 |
| 同步 | 离线优先：客户端先写本地库，再进入 outbox；推送时按 `base_version` 与字段级 HLC 合并；按 `server_seq` 增量拉取；WebSocket 通知 | v0.3.0 |
| 冲突 | 同一字段以最后修改为准，不同字段自动合并；长文本做三方合并，合并失败时把败方存入修订历史 | v0.3.0 |
| 工作日志加密 | TLS 1.3（正式版只信任 Let's Encrypt 根证书），再叠加应用层 X25519/HKDF/AES-256-GCM 载荷加密；落库采用信封加密，主密钥在服务器 `.env` 中（ADR-006、ADR-012） | v0.3.0 |
| 笔记 | Markdown 与富文本两种编辑方式，正文统一存 Markdown；富文本编辑器是打包进 App 的 Tiptap 页面（WebView，CSP 禁止脚本注入与网络访问）；标签与关联存为多行文本，并发修改按补丁合并（ADR-007） | v0.4.0 |
| 搜索 | 客户端本地 SQLite FTS5（trigram 分词）外部内容索引，随记录保存更新；覆盖四个模块，可按模块、日期筛选，分类、账户、借贷对方命中时带出相关流水；可离线使用（ADR-010） | v0.7.0 |
| 提醒 | 优先使用本地精确闹钟；服务端在推送事务内重建待发提醒（PostgreSQL 表 + 轮询调度，不用 asynq），到时只给尚未同步到该备忘录、或不能本地提醒的设备补发极光推送，推送不含内容；系统日历单向写入（ADR-008） | v0.5.0 |
| 记账 | 账户、两级分类、借贷、流水四个同步实体；金额以分为单位的整数字符串并加密；预置分类按账号生成固定 ID，多设备不重复；余额、分类占比、趋势、净资产全部本地计算（ADR-009） | v0.6.0 |
| 导出 | 服务端后台任务（PostgreSQL 表领取，不用 asynq）解密所选模块，生成含 xlsx、Markdown、ICS、CSV、JSON 与附件的 zip，上传对象存储，预签名下载；文件保留 24 小时，完成后推送通知（ADR-010） | v0.7.0 |
| 部署与备份 | 单台服务器 Docker Compose；Release Please 发布后由 GitHub Actions 构建、经 SSH 部署，失败自动回滚；每 14 天把数据库、附件和配置用 age 加密后上传到只能写入的异地 OSS，保留 6 份（ADR-012） | v0.9.0 |
| 正式 APK | 发布时由 GitHub Actions 构建并签名，核对签名证书指纹后附到 GitHub Release | v1.0.0 |
| 管理后台 | 独立的管理员账号与会话：令牌受众与签名密钥都与用户令牌不同，Refresh Token 放 HttpOnly Cookie；认证按路由前缀分流，管理员令牌访问用户接口返回 403；只读查看用户配置（设置、设备、同步状态、存储），手机号脱敏；所有查看与管理操作写审计日志（ADR-011） | v0.8.0 |

## 接口约定

- 契约文件：[`server/api/openapi.yaml`](../../server/api/openapi.yaml)，由它生成 Go 服务端桩（oapi-codegen strict server）和 TS 类型（openapi-typescript）
- 统一信封：`{ success, data, error: { code, message, details }, meta, requestId }`
- 每个请求都带 `X-Request-ID`：客户端传入合法值时沿用，否则服务端生成 UUIDv7。响应头和信封里会返回同一个值
- 错误码用大写蛇形字符串表示，HTTP 状态码表示错误类别；5xx 不向客户端返回内部细节
- 访问日志只记录路径，不记录查询串，避免手机号、验证码等写入日志

## 服务端目录约定

```
server/
├─ api/openapi.yaml            接口契约
├─ cmd/api                     HTTP 服务入口
├─ internal/apigen             生成代码（勿手改）
├─ internal/platform/          与业务无关的基础设施：config / logging / httpx / db / cache / storage / sms / pusher / crypto
├─ internal/system             健康检查与系统信息
├─ internal/server             路由组装与优雅关闭
└─ internal/<模块>             auth / worklog / note / memo / ledger / sync …（按领域划分）
```

各模块的处理器类型都命名为 `Handler`。在 `internal/server` 中通过类型别名嵌入到 `API` 结构体，由它统一实现生成的 `StrictServerInterface`。
